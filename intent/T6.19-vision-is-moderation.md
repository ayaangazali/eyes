## Why
The operator: the classifier must not judge whether the answer is right. A "does not answer the question" guess held honest workers' pay in review. The agent gets the photo and the answer, judges them, and uses `dispute_answer` when the answer is wrong.

## What
- `packages/verify`: the judge sees only `{ photo_url }` and returns `{ allowed, reason, prominent_faces, confidence }`. Blocked: prominent face or person as the subject, nudity/sexual content, violence/gore, private interiors through windows, documents/screens with personal info, a license plate readable as the subject, not a real photo (blank, black, screenshot). clef-omni asks `safe_to_share` + `prominent_faces`; unsure or failed goes to Claude when configured, else not allowed (manual review). Timeout or error: "Safety check unavailable; the photo needs manual review."
- Payout: GPS + fresh + moderation pass auto-approves. Faces still delete the photo (ADR-014). Any moderation fail sends the task to `needs_review` with the reason (worker can reply HELP), and the agent gets `photo_url: null`.
- API fields `vision_ok` / `vision_reason` kept; schema descriptions, ask_eyes / await_answer / server instructions and llms.txt now say Eyes checks location, freshness and that the photo is safe to share, not whether the answer is correct.
- Label "Photo is safe to share" on the capture page, ChatGPT widget card, dashboards, landing and docs.

## Decisions & alternatives rejected
See ADR-025: field names kept for agents; no advisory correctness score; one moderation question instead of one per category.

## Verification
- `packages/verify/src/index.test.ts`: approves a capture with a wrong answer text when moderation allows it and the judge sees only the photo URL; a blocked photo is held with the moderation reason; Claude gets only the image and "Moderate this photo."; clef sends exactly `safe_to_share` and `prominent_faces`, blocks when sure-unsafe, sends unsure photos to review, and fails closed when clef is down without Claude.
- `packages/engine/src/engine.int.test.ts` (local Postgres): a blocked photo is kept in storage for ops, the task is `needs_review`, and `get_task` returns `photo_url: null`; an allowed photo is delivered.
- live-verified: see the PR #94 report.
