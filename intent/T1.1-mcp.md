## Why
Agents reach Eyes through this app: eight MCP tools and an identical REST mirror over `EyesService`, plus the public worker API the capture page posts to. It is also the composition root that wires engine, adapters and fakes, so every transport shares the one seam from ADR-003.

## What
- `src/server.ts` `createServer`: mcp-use 2.10.0 server; bearer auth on `/mcp` and `/v1/*` (signup public, scheme case-insensitive); all 8 `TOOLS` with exact schemas, annotations and LLM descriptions (example plus next step each); errors as `EyesError.toBody()`; `await_answer` gets the request AbortSignal and reports progress every 5 s when the client sent a token; REST mirror of `HTTP_ROUTES` (`invalid_input` with `issues`); `/w/*` with CORS for `worker_web_url`; capture checks the link token before parsing, trims fields, and accepts only JPEG, PNG or WebP by magic bytes; vendor routes; docs served from `docs/public/<url path>`; `/healthz`.
- `src/http.ts` `toNodeListener`: the `node:http` bridge `main.ts` serves through: body limits picked by content-type, JSON pre-validation and content-type cleanup for non-`/mcp` paths, abort on disconnect, request logs of the parsed pathname with link tokens redacted.
- `src/geo.ts`: Nominatim `Geo`; `FAKE_PLACES` and in-range "lat,lng" strings resolve first; in-memory cache; 5 s timeout; null on no hit.
- `src/main.ts`: env to `AppConfig` (`email_domain` from `PRIMITIVE_DOMAIN`, ADR-007) and `DbConfig`; fakes unless `EYES_PROVIDERS=live` plus the adapter's key; one log line per provider; `expireOverdue` every 30 s; listens on `PORT`/`HOST` (3000, 0.0.0.0).

## Decisions & alternatives rejected
- Own `node:http` adapter instead of `server.listen`: mcp-use's bridge decodes bodies as text (binary photos corrupted) and buffers whole bodies before auth. The adapter streams bytes, rejects `content-length` over the limit before reading, counts chunked bodies and then drains the rest so the client really receives the 413; closing the socket instead lost the 413 to EPIPE in tests. `@hono/node-server` was not added: a new dependency for about 60 lines.
- The 21 MB limit applies only to `POST /w/offers/:token/capture` with a `multipart/form-data` content-type that does not mention `application/json`; everything else gets 1 MB. mcp-use's global `jsonBodyMiddleware` runs `request.clone().json()` on any JSON content-type before our routes, so a path-only limit let 21 MB of JSON reach it.
- For non-`/mcp` paths the adapter strips content-type from GET/HEAD and empty bodies and answers invalid JSON itself with `invalid_input` (400), so that middleware never turns a valid REST call into its plain-text 400. `/mcp` is passed through untouched.
- mcp-use's request logger is off because it printed link tokens; the adapter logs `METHOD path status ms` with `/w/offers`, `/w/connect` and `/topup` tokens replaced by `<token>`.
- Photo type comes from magic bytes, not the client's label, and is stored with the detected type.
- Stripe sub-app is forwarded only for its three paths: the stub's `all("*")` at `/` shadowed `/mcp` (reproduced).
- Status wording in the instructions, `await_answer` and `get_task` follows the engine: expired means nobody answered before the deadline and refunded means the agent cancelled; both refund the escrow.
- Tool handlers catch every error: mcp-use returns a thrown error's raw message (reproduced). The clock in `main.ts` is real; `fakeClock` is frozen.

## Assumptions
- mcp-use per the vendor note and `dist/*.d.ts`: `c.set` reaches tools through `ctx.get`; `reportProgress` returns false without a progress token; `server.fetch` needs no `listen`.
- Offer links are `signToken(config.link_secret, ...)` tokens (engine, T1.2). Nominatim wants an identifying User-Agent and at most 1 request/s.
