## Why
Agents reach Eyes through this app: eight MCP tools and an identical REST mirror over `EyesService`, plus the public worker API the capture page posts to. It is also the composition root that wires engine, adapters and fakes, so every transport shares the one seam from ADR-003.

## What
- `src/server.ts` `createServer`: mcp-use 2.10.0 server; bearer auth on `/mcp` and `/v1/*` (signup public, scheme case-insensitive); all 8 `TOOLS` with exact schemas, annotations and LLM descriptions (example plus next step each); errors as `EyesError.toBody()`; `await_answer` gets the request AbortSignal and reports progress every 5 s when the client sent a token; REST mirror of `HTTP_ROUTES` (`invalid_input` with `issues`); `/w/*` with CORS for `worker_web_url`; capture checks the link token before parsing, trims fields, and accepts only JPEG, PNG or WebP by magic bytes; vendor routes; docs served from `docs/public/<url path>`; `/healthz`.
- `src/http.ts` `toNodeListener`: the `node:http` bridge `main.ts` serves through, with body limits, abort on disconnect and request logs with link tokens redacted.
- `src/geo.ts`: Nominatim `Geo`; `FAKE_PLACES` and in-range "lat,lng" strings resolve first; in-memory cache; 5 s timeout; null on no hit.
- `src/main.ts`: env to `AppConfig` and `DbConfig`; fakes unless `EYES_PROVIDERS=live` plus the adapter's key; one log line per provider; `expireOverdue` every 30 s; listens on `PORT`/`HOST` (3000, 0.0.0.0).

## Decisions & alternatives rejected
- Own `node:http` adapter instead of `server.listen`: mcp-use's bridge decodes bodies as text (binary photos corrupted) and buffers whole bodies before auth. The adapter streams bytes, rejects `content-length` over the limit before reading, counts chunked bodies (21 MB capture, 1 MB elsewhere) and then drains the rest so the client really receives the 413; closing the socket instead lost the 413 to EPIPE in tests. `@hono/node-server` was not added: a new dependency for about 60 lines.
- mcp-use's request logger is off because it printed link tokens; the adapter logs `METHOD path status ms` with `/w/offers`, `/w/connect` and `/topup` tokens replaced by `<token>`.
- Photo type comes from magic bytes, not the client's label, and is stored with the detected type.
- Stripe sub-app is forwarded only for its three paths: the stub's `all("*")` at `/` shadowed `/mcp` (reproduced).
- Tool handlers catch every error: mcp-use returns a thrown error's raw message (reproduced). The clock in `main.ts` is real; `fakeClock` is frozen.

## Assumptions
- mcp-use per the vendor note and `dist/*.d.ts`: `c.set` reaches tools through `ctx.get`; `reportProgress` returns false without a progress token; `server.fetch` needs no `listen`.
- Offer links are `signToken(config.link_secret, ...)` tokens (engine, T1.2). Nominatim wants an identifying User-Agent and at most 1 request/s.

## Verification
- `pnpm test`: 24 passed in apps/mcp (3 files). `http.test.ts` uses real sockets: a 2 MB random-byte JPEG reaches the stub with the same sha256 and the log line shows `<token>`; 256 MB declared `content-length` to unauthenticated `/mcp` gets 413 without `authenticate` being called; a 2 MB chunked body gets 413; MCP over SSE returns progress. `server.test.ts` covers 401 (incl. `POST /v1/tasks`), lowercase bearer, eight tools with hints, EyesError and unknown errors on MCP and REST without leaks, `invalid_input` issues, signed and expired tokens, HTML labelled image/jpeg rejected, malformed multipart, blank fields. The geo test covers out-of-range coordinates.
- Mutation checks: removing the content-length check, the chunk counter, the token check, the image check or the coordinate range made 6 tests fail; decoding the body as text the way mcp-use's bridge does failed the binary test.
- Scratch run with 256 MB to `/mcp`: chunked 413 with RSS 128 to 131 MB, declared 413 with RSS 135 MB; a client disconnect aborted the `await_answer` signal.
- `pnpm verify:fast`: pass. `pnpm test:integration` on eyes_t11: 4 passed. live-verified: no.
