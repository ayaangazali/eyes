## Why
Coverage was measured only for the unit, contract, and safety projects. Within those, `packages/db/src/rpc.ts` sat at 4% lines, `storage.ts` at 58%, `migrate.ts` at 9% (it only runs in the integration project), and `apps/web/dashboard/src/server.ts` at 76% (its startup block is untested). `apps/edge/api/worker.js`, `apps/edge/monitor/worker.js`, and the web worker's `api.ts`, `join.ts`, and `capture.ts` had no coverage at all, so routing, the container retry buffer, the uptime alert state machine, and the join form validation could regress unseen.

## What
- Tooling: `@vitest/coverage-v8@5.0.5` as a root devDependency. `pnpm coverage` runs the unit, contract, and safety projects with coverage. `pnpm coverage:integration` runs the integration project and needs `DATABASE_URL`. `vitest.config.ts` measures `apps/`, `packages/`, and `cli/` sources and excludes tests, `dist`, `node_modules`, `scripts/`, and `apps/mobile/ios`.
- `packages/db`: `rpc.test.ts` covers InsForge and Postgres calls, HTTP failure messages, and `eyes:<code>` parsing into `EyesError` (rpc has no retries, so none are tested). `storage.test.ts` adds presigned and direct uploads, upload refusal, unknown methods, and missing config. `migrate.int.test.ts` runs migrations in a throwaway schema.
- `apps/edge/api/worker.js`: routing (`ORIGIN` proxy, `workers.dev` to the container), `x-forwarded-for` replaced by `cf-connecting-ip`, `host` removed, `scheduled()` calls `ensure()`, and the `EyesServer` retry buffer with a 503 at the deadline.
- `apps/edge/monitor/worker.js`: probe classification (non-200, non-JSON, `ok` false, providers not live, wrong db, timeout), state transitions (two failures give one down alert, recovery gives one up alert with minutes, no repeats), and a failed send leaves state unwritten.
- `apps/web/worker/src`: `api.ts` error words and `call()`, `join.ts` `toE164` and validation (`join.ts` gains one `export` on `toE164`, no behaviour change), and `capture.ts` pure helpers. Tests stub globals; no DOM dependency is added.
- `apps/web/dashboard/src/server.ts`: the uncovered startup and error branches.

## Decisions & alternatives rejected
- Stub `document` and `fetch` rather than add happy-dom or jsdom: the web worker code is small, and a DOM dependency would be heavier than the tests.
- Export `toE164` rather than move it to a new module: one line, no behaviour change, no new file.
- `apps/web/dashboard/src/server.ts`: env-to-database selection moved into an exported `dbFromEnv()` so the startup branches can be tested. Behaviour unchanged.
