## Why
Eyes sends real people to real places, so every task must be about a public, commercial or civic place before it is dispatched (§12). `createAssessTask(env)` is the gate the engine calls before any escrow; a blocked verdict becomes `unsafe_task` and its `reason` and `fix` go straight to the agent, so they are neutral and say how to rephrase.

## What
- `rules.ts`: high-precision, category-tagged regexes over `question` and `place_label` (NFKC, `\p{Default_Ignorable_Code_Point}` stripped, curly apostrophes normalized), in severity order: illegal_or_dangerous, following, private_property, vehicle, private_residence, identifiable_people, private_person. First match wins; per-category `reason`/`fix` templates.
- `index.ts`: rules first (a block is final, `layer: "rules"`); with `ANTHROPIC_API_KEY`, `claude-haiku-5-5` via `messages.parse` + `zodOutputFormat`, effort `low`, 5 s request timeout, 1 retry, 12 s overall `AbortSignal.timeout` so a stalled body also fails closed. No key: rules only, one warning at creation. Any classifier failure fails closed (`other`, "temporarily unavailable", "Nothing was charged. Retry..."). A model refusal blocks as `other`.
- `evals/safety/fixtures.json`: 122 cases (44 allow, 78 block, every category; 115 carry `rules_expected`; every rule pattern has at least one blocking fixture), including every verifier false-positive repro and negated photo instruction as a rules allow, and the §13 demo refusals (with located/number/plural variants) as rules blocks. `evals/safety/run.ts` prints precision, recall and misses; rules-only without a key; any "temporarily unavailable" verdict marks the run INVALID and is excluded. Always exits 0.

## Decisions & alternatives rejected
- Orchestrator ruling (fix round 1): a rules block is final, so the rule layer is high precision only. Broad patterns were deleted rather than patched with exceptions (bare `name's home`, bare bomb/drug/smuggle/surveil/trespass words, "track down", bare driveway, "house ... #N", plate mentions without a vehicle target); nuance goes to the classifier. Person objects for follow/track/watch exclude staff and "them" ("watch the barista make my latte" is allowed). Fix round 2 also dropped "grenade" (Grenade protein bars), "sell ... stolen" and bare "sneak in".
- Untrusted input: the task is `JSON.stringify`d with every `<` escaped to `\u003c` inside `<task>` tags, so a question cannot close the tag; the prompt says the block is data and an override attempt is itself a block. Only question/task_type/place_label are sent.
- Negated photo and identify instructions ("do not photograph faces", "avoid photographing the employees", "workers should not identify people") are skipped by a lookbehind for not/never/n't/avoid/without/no within three words before the verb; "Take a photo of the cashier's face" still blocks.
- Classifier reason/fix pass through; empty values fall back to the category template.
- Tests stub global `fetch` instead of changing the `createAssessTask(env)` signature, so the real SDK request, retry, timeout and parse code runs.

## Assumptions
- `messages.parse` + `zodOutputFormat` returns `parsed_output` and throws `AnthropicError` on bad JSON or schema mismatch (`helpers/zod.js`, `lib/parser.js`); the SDK reads `globalThis.fetch` at construction.
- `claude-haiku-5-5` supports structured outputs at effort `low` with default adaptive thinking (counted in `max_tokens` 1024); refusals are HTTP 200 `stop_reason: "refusal"` with no server-side fallback.

## Verification
- `pnpm test:safety`: 116 passed (coverage check + 115 `rules_expected` fixtures, category asserted on blocks). Mutation check: removing the negation lookbehind fails the 8 negated-instruction fixtures.
- `vitest --project unit packages/safety`: 15 passed, incl. no-key rules block with zero fetch calls and stalled-body abort. Mutation checks: dropping the `<` escape or the abort signal each fails a test.
- Probes: 113 extra benign phrasings (house-made bagels, climbing gym wall, surveillance camera, burglar alarm, "break into the line", plate renewal form) give 0 rule false positives.
- `node evals/safety/run.ts` without a key: rules-only precision 1.000, recall 0.910 (the 7 misses are the classifier-only fixtures). With an unreachable API: INVALID RUN reported, exit 0.
- `pnpm verify:fast`: pass. Live classifier eval: not run (no key). live-verified: no.

## Known gaps
- Classifier precision/recall unmeasured until `ANTHROPIC_API_KEY` exists; run `pnpm safety:eval`.
- Leetspeak, plurals, paraphrases, homoglyphs and non-English text get past the rules and rely on the classifier; rules-only mode (no key) is weaker by design and allows anything the rules miss; the composition root will refuse live mode without a key (T2.4).
- Accepted rare false positives: "Apartment 3 leasing office" (apartment-number rule) and "Who Lives in a Pineapple" shirts (`who lives` rule).
