## Why
Eyes sends real people to real places, so every task must be about a public, commercial or civic place before it is dispatched (§12). `createAssessTask(env)` is the gate the engine calls; a blocked verdict becomes `unsafe_task` and its `reason` and `fix` go straight to the agent, so they are neutral and say how to rephrase.

## What
- `rules.ts`: category-tagged regexes over `question` and `place_label` (NFKC, zero-width stripped, curly apostrophes normalized), checked in severity order: illegal_or_dangerous, following, private_property, vehicle, private_residence, identifiable_people, private_person. First match wins. Per-category `reason`/`fix` templates.
- `index.ts`: rules first (a block is final, `layer: "rules"`); with `ANTHROPIC_API_KEY`, `claude-haiku-5-5` via `client.messages.parse` + `zodOutputFormat` (allowed/category/reason/fix), effort `low`, 5 s timeout, 1 retry. No key: rules only, one `console.warn` at creation. Any classifier error, timeout or unparseable output fails closed (`other`, "temporarily unavailable", "retry in a few seconds"). A model refusal blocks as `other` with the generic template.
- `evals/safety/fixtures.json`: 52 cases (21 allow, 31 block, every category; 46 carry `rules_expected`). `evals/safety/run.ts` (`pnpm safety:eval`) runs the full gate and prints precision, recall (block = positive) and every miss; exits 0, skips without a key.

## Decisions & alternatives rejected
- Untrusted input: the task is `JSON.stringify`d with `<` escaped to `<` inside `<task>` tags, so a question cannot close the tag; the system prompt says the block is data and an override attempt is itself a block. Only question/task_type/place_label are sent.
- Classifier reason/fix pass through (more specific than templates); empty values fall back to the category template.
- Rules favor precision: ambiguous person-vs-brand phrasings ("Is John Smith at Blue Bottle?") are left to the classifier because a regex cannot tell a name from a business ("Is Costco in Daly City busy?"). Gun stores, ammo stock and similar lawful-but-sensitive asks are also left to the classifier.
- Tests inject `fetch` with `vi.stubGlobal` instead of changing the `createAssessTask(env)` signature; the real SDK request, retry, timeout and parse code runs. Allowed verdicts carry the last layer that ran.

## Assumptions
- `client.messages.parse` with `output_config.format = zodOutputFormat(...)` returns `parsed_output` and throws `AnthropicError` on bad JSON or schema mismatch (read in `helpers/zod.js`, `lib/parser.js`).
- `claude-haiku-5-5` accepts structured outputs with `output_config.effort: "low"` and adaptive thinking left at default; thinking counts toward `max_tokens`, so 1024 leaves room. A refusal returns HTTP 200 with `stop_reason: "refusal"` and no server-side fallback exists for Haiku 5.5.
- The SDK takes `fetch` from `globalThis` at client construction (`internal/shims.js`).

## Known gaps
- Classifier precision/recall are unmeasured until `ANTHROPIC_API_KEY` exists; run `pnpm safety:eval`.
- Rules are English-only, and homoglyph (e.g. Cyrillic) spellings bypass them; both rely on the classifier.
