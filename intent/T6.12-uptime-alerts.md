## Why
The API is a pass-through to a Mac behind a tunnel (`apps/edge/api`). When it breaks, nothing tells the operator. The monitor has to live outside the server, because the server may move hosts and cannot report its own death.

## What
- `apps/edge/monitor` is a separate Cloudflare Worker, `eyes-monitor`, with cron `* * * * *`.
- Each tick GETs `HEALTH_URL` (default `https://api.eyes.pictures/healthz`, 10 s timeout, UA `eyes-monitor/1.0`). Healthy = HTTP 200, `ok` true, every provider `live`, `db` `insforge`.
- Two consecutive failures send "Eyes API is down: <reason>". The next healthy tick sends "Eyes API is back up (down N min)". Silent otherwise.
- State is one key, `state`, in KV namespace `EYES_MONITOR` (id `dd0114db8cb24d46be6d69b54385d638`).
- Channel: Inkbox iMessage to `ALERT_PHONE` (+15109009898), via the Inkbox REST API with secrets `INKBOX_API_KEY` and `INKBOX_AGENT_HANDLE`.
- Email via Primitive was tried first and refused: Primitive returned HTTP 403 for `jerry@xiao.sh` (recipient gates: `xiao.sh` is not a confirmed or known recipient). Its secrets were deleted from the Worker.
- A failed send throws, so state is not written and the next tick retries.

## Decisions & alternatives rejected
- Separate Worker, not a cron in `apps/edge/api`: the monitor must keep working when the API moves or dies.
- One URL, one channel, one KV key. A second channel waits until one is needed.
- Inkbox called with `fetch`, not the SDK: the monitor sits outside the pnpm workspace and needs no bundle.
