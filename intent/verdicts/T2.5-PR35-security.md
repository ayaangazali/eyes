- [minor] packages/core/src/schemas.ts:294 + packages/payments/src/index.ts:296: OwnerPolicyInput accepts sub-cent values and any numeral `Number()` takes, and `usdToCents` float rounding is not consistent. 0.005 becomes 1 cent, 1.005 becomes 100 cents, 3.335 becomes 334 cents, and "0x10" becomes $16. These are caps, not money movement, and they still pass ADR-001 because cents are stored as integers. The bounds 0..100 and 0..1000 hold. Repro: POST /owner/<p>/policy `max_bounty_usd=1.005&daily_cap_usd=0.005` -> 303, agents row m=100 d=1; `max_bounty_usd=0x10&daily_cap_usd=1` -> 303, m=1600. Suggested fix: add `.multipleOf(0.01)` to both fields (or a `/^\d+(\.\d{1,2})?$/` check in formNumber) so the server rejects what the form's step=0.01 already rejects.
- [minor] packages/engine/src/index.ts:552 / packages/payments/src/index.ts:308: duplicate task types are saved as-is and echoed to the agent by get_spend_policy. Repro: POST `...&allowed_task_types=is_open&allowed_task_types=is_open` -> 303, allowed_task_types = {is_open,is_open}. Suggested fix: pass `[...new Set(policy.allowed_task_types)]` to the RPC.
- [minor] packages/engine/src/index.ts:304 (with schemas.ts:325): the agent picks the owner link's destination itself, because it supplies owner_email at signup. An agent that names an inbox it can read gets the `p:` link and can raise its own limits to 100/1000. Isolation holds after signup: a prompt-injected agent mid-session cannot get the link, since it goes out only once, from eyes@<domain>, and replies to that address map to no agent and are ignored (primitive.ts:325). ADR-011 accepts this design residual; the code does not violate the contract. Repro: signup {name, owner_email: <agent-controlled inbox>} -> that inbox receives /owner/<p>. Suggested fix (follow-up ADR): also send the owner link to the Stripe Checkout payer email on the first top-up, or show the owner email on the top-up page.
- [minor] packages/engine/src/index.ts:159: public signup sends an Eyes-branded email to any address, carrying up to 80 attacker-chosen characters (the agent name). JSON quoting blocks header and newline injection. Subject and sender are constant, and owner_email rejects CRLF, comma lists and angle brackets with 400. What remains is a low-rate phishing relay: a name such as `URGENT: account locked, verify at https://evil.example/login` is delivered verbatim. With T4.1 (5/hour/IP) this is deferrable. Repro: POST /v1/signup {"name":"URGENT: ... https://evil.example/login","owner_email":"victim@example.com"} -> 200, email line 1 contains the URL. Suggested fix: keep it in Known gaps, track it as an ADR-010 deferred issue, and consider leaving the agent name out of the email body.
