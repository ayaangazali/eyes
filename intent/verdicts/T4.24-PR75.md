# T4.24 PR #75 verdicts

## Round 1: FAIL (1 major, 4 minor)
- major, `packages/comms/src/inkbox.ts` `sendPaid`: the simulated notice from `settle()` for a worker with no payout account went out under `paid:<task>:<phone>`, the same key as the real paid text. Inkbox replays a reused key instead of sending, and the task stays `verified`, so after Stripe goes live and that worker onboards, the real transfer's "you've been paid $3" would be swallowed and the worker's last text would still say "No money was sent". Fixed: the simulated notice uses `accepted:<task>:<phone>`; new unit test "keys the simulated paid notice apart from the real one" fails on c461a97 (`expected [ 'paid:t1:+14155550123', ... ] to deeply equal [ 'accepted:t1:+14155550123', ... ]`). ADR-022 drops the "keeps the paid key" argument and gives the mode-switch reason.
- minor, intent and ADR said the money flow and task status were unchanged, but the simulated connect page no longer creates a fake account, so a new worker's verified tasks stay `verified` with escrow held. Fixed in the text, not the code: creating `acct_fake_...` ids now would break those workers' real onboarding links after go-live, because `workerConnectUrl` reuses a stored account id. ADR-022 also says what happens to those tasks at go-live.
- minor, `apps/web/worker/index.html`: the `#simulated` notice was visible in the static HTML and hidden by `join.ts`, so a live build flashed "This is a test server" and showed it with scripts off. Fixed: `<body data-live-payouts="%VITE_LIVE_PAYOUTS%">`, filled in by Vite at build time, and CSS hides the notice or the live sentences from it; the `join.ts` toggles are gone (the file is back to origin/main). New worker e2e "the payout notice is right in the static page, before any script runs" (scripts off, both builds) fails on c461a97 (`expect(locator).toBeHidden() failed`).
- minor, `apps/mcp/src/server.test.ts` page-headers test: its config defaulted to simulated payouts, so `/w/connect/not-a-token` hit the simulated page and never the `workerConnectUrl: refuse` error page. Fixed: the shared test config sets `live_payouts: true`.
- minor, docs: `VITE_LIVE_PAYOUTS=true` added to the Stripe row and the Sites rebuild command in `docs/PLAN.md` section 4 and to the `docs/DEMO.md` pre-demo checklist. STATUS.md untouched.
- Checked by the verifier: live mode unchanged.
