## Why
On a deploy with the fake Email provider, signup with `owner_email` told the agent "We emailed your user ... a private control link", so the agent told its human to check an inbox that would never get the mail (PM journey audit, Journey 3 step 2, promise R30). The fake provider resolves like a real send, so the engine could not tell the difference.
## What
- `AppConfig.email_delivery`, default `false` (ADR-018). `main.ts` sets it from `liveProviders(env).email`, the same decision that wires `createPrimitiveEmail`.
- `signupAgent`: when `email_delivery` is false and the send did not throw, next_step says owner email delivery is not set up on this server, nothing was sent to that address, and the user can get the control link from the Eyes operator (`pnpm owner-link <agent_id>`). The send still goes through `providers.email`. True keeps the old "We emailed" text; a throwing send keeps "We could not email".
- `engine.int.test.ts`: deps pulled into a typed `deps` const so one test can build a second service with `email_delivery: true`.
## Decisions & alternatives rejected
- Config flag over a `simulated` marker on the Email provider: no provider interface change, and the entry point already decides live vs fake.
- Keep sending when delivery is off: the fake outbox is how tests and the demo harness read the owner link.
- `creditTopup` unchanged: checked that it returns nothing to the agent, the webhook replies `{ received: true }`, and a successful send logs nothing, so it makes no claim.
## Assumptions
- `pnpm owner-link <agent_id>` passes the id through to `scripts/owner-link.ts` (`process.argv[2]`). Checked: `EYES_LINK_SECRET=... EYES_PUBLIC_API_URL=... pnpm owner-link <uuid>` prints an `/owner/<token>` URL.
