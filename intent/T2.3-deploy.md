## Why
G1 and G2 need the real server reachable over HTTPS by Claude, by phones and by three vendors' webhooks. Keys and logins are with the humans, so everything that does not need a key is prepared and proven locally first.

## What
- `Dockerfile` (Node 24 slim, workspace install filtered to `@eyes/mcp...`, runs `node apps/mcp/src/main.ts` on 0.0.0.0) and `.dockerignore`. Manufact uses a committed Dockerfile as-is (docs/vendor/mcp-use-manufact.md).
- `scripts/insforge-migrate.ts`: posts each `packages/db/migrations/NNN_*.sql` to InsForge `POST /api/database/migrations` with the admin key; 409 is treated as already applied.
- `docs/DEPLOY.md`: runbook for InsForge, Manufact, Sites, webhooks and the G1/G2 live smoke checklist.

## Decisions & alternatives rejected
- Worker web is deployed to InsForge Sites as a prebuilt static `dist` (env baked in at build) instead of letting Vercel install the pnpm workspace, which needs the root lockfile.
- One image runs everywhere; if the Manufact gateway does not forward non-`/mcp` paths, the same image runs on another host (ADR-004).

## Assumptions
- InsForge migrations endpoint accepts `{version, name, sql}` and rejects duplicate versions (docs/vendor/insforge.md, "Database: SQL migrations"); the 409 handling is unverified (first run applied everything fresh).
- InsForge Sites deploys a static folder without a build step (docs/vendor/insforge.md, "Hosting"); verified 2026-10-17.
