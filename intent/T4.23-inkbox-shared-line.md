## Why
The Inkbox key we got is on the free plan. Its org has no dedicated iMessage line: `inkbox.imessages.listNumbers()` returns `[]`, and `inkbox.imessages.getTriageNumber()` returns the shared router +16504849720 with connect command `connect @your-handle`. On the shared line a worker's texts reach our identity (`hackathon`) only after the worker texts `connect @hackathon` to the router, and the SDK says outbound sends on shared service need the recipient to connect first. The JOIN page only offered "Text START to <number>", so a worker who followed it would text START into the router, reach no identity, and never get a task.

## What
- New build-time `VITE_INKBOX_CONNECT` for the worker web. When it is set, the "You're in" steps show two text buttons in order: `First text "<connect command>" to <number>` (sms body is the command) and `Then text START to <number>`. Without it the page is unchanged: one `Text START to <number>` button.
- The sms body is URL-encoded, so `connect @hackathon` survives the `sms:` link.
- DEPLOY and PLAN say how to tell the shared line from a dedicated one and which env to set for each.

## Decisions & alternatives rejected
- Build-time env, like `VITE_INKBOX_NUMBER`, not a field on `JoinWorkerOutput`: the connect command is fixed per deployment, the page is rebuilt anyway when the number changes, and a new response field is a frozen-contract change (ADR needed) for a value the server would only echo.
- Two texts, not one message with both lines: Inkbox documents the connect command as its own message to the router; whether text after it in the same message reaches the identity is not documented, and a worker who loses START has to find out why.
- Not resolved at runtime from `getTriageNumber()`: that needs the worker web to call Inkbox or the server to proxy it. The router number changing mid-event is unlikely, and a rebuild fixes it.

## Assumptions
- After `connect @hackathon`, the worker's next message (START) arrives as `imessage.received` for identity `hackathon` with `remote_number` set to the worker's phone. To be checked live with the first real text (G1).
