## Current status (2026-10-18)

Looks good acceptance is deployed, alongside [Ask again and dispute review holds](T6.66-dispute-review-hold.md). Acceptance remains feedback only: it does not charge, release payment or remove dispute rights. Current-card in-chat visual proof is still quota-blocked; the scoped checks below are not that proof.


## Why

The delivered-answer card needs a meaningful Looks good action that survives reload without charging twice or making worker payment depend on user feedback.

## Contract

`accept_answer({task_id})` records the authenticated owning agent's positive feedback, not machine photo verification. Only answered verified/paid tasks qualify; missing, foreign, unanswered, needs_review and disputed tasks do not. The first acceptance timestamp is stored on the existing task, with one `answer_accepted` event containing the agent ID. The task-row lock makes repeated and concurrent calls return the first timestamp without duplicate events. Existing task reads expose `accepted_at` and retain the existing task status.

The Looks good button uses the shared MCP Apps/ChatGPT call bridge. Pending calls cannot double-submit; failures preserve the answer and allow retry. Accepted state survives refresh. Acceptance changes no ledger entries, balances, payout conditions or dispute rights. Migration 036 is additive; older application versions ignore the nullable new column. Rollback means redeploying older application code while retaining feedback data, not dropping the column.

## Verification

Scoped local PostgreSQL tests exercise a real HTTP listener and MCP client with fake external providers: authentication, ownership, all status boundaries, missing submission, concurrent repeat acceptance, restart/read persistence, one feedback event, unchanged ledger/balance/transfers/messages and subsequent dispute. Widget tests exercise both host bridges, pending/error/reload states and retain existing classifier/dispute controls. Normal PR CI provides repository-wide gates. No live task is accepted and no real payment is made.
