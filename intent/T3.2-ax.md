## Why
An agent that has never heard of Eyes must get from "here is a URL" to a verified answer using only public docs: sign up, hand the top-up link to its human, connect MCP, then quote, ask and loop on await. These are the files apps/mcp serves at `/llms.txt`, `/llms-full.txt`, `/openapi.json` and `/.well-known/agent-card.json`, plus a CLI so the same capabilities work from a shell (§9) without ever escrowing twice on a retry.

## What
- `docs/public/llms.txt` (hand-written, 91 lines, llmstxt.org shape): scope (public places only), pricing, escrow and refunds, the 4-step quickstart with the exact `claude mcp add` command and a `.mcp.json` snippet, every status including `needs_review` (escrow held until a human review pays or refunds), errors with `fix`, the MCP "Input validation error" exception, `rate_limited` and safe key reuse after a rejected ask, links.
- `docs/public/agents.md` and `docs/public/robots.txt` (allow all, Claude-User and ChatGPT-User named): Armature scanner cheap wins.
- `cli/src/docs.ts` generates `openapi.json` (OpenAPI 3.1, every `HTTP_ROUTES` entry except health, webhooks, browser redirects and the `/w/*` worker routes; schemas via `z.toJSONSchema`; bearer scheme; `Error` with `error`, `message`, `fix`; `requestBody.required` only when the body schema has required fields), `llms-full.txt` (llms.txt plus signup, per-tool REST route, summary, example and JSON Schemas, and the `ERRORS` catalog) and `.well-known/agent-card.json`. `pnpm --filter @eyes/cli gen:docs` writes them, then Biome formats the JSON.
- `cli/src/main.ts`: `eyes signup|ask|await|quote|status|cancel|dispute|balance|policy`, `node:util` parseArgs, `--json` (one JSON object per line), `-h/--help` per command (works before config is read), config at `~/.config/eyes/config.json` (0600, chmod also on an existing file) with `EYES_API_URL`/`EYES_API_KEY` overriding it. Arguments are checked locally against the contract schemas (`AskEyesInput` etc.), so numbers, bounds and task ids fail with a fix before any request.
- `ask` takes `--idempotency-key` (else a UUID), `--no-photo` and `--no-wait`. It prints `{"idempotency_key": ...}` to stderr before the POST, then the ask result with the key. A failed or Ctrl-C'd ask (`interrupted`, exit 130) carries the key in the error and its fix. The await loop (`ask` and `await <task_id> [--timeout <seconds per poll>]`) retries in place on `rate_limited` (sleeps `retry_after_s`), network errors and any HTTP status >= 500, HTML gateway pages included, with 1, 2, 4 .. 30 s backoff, and gives up after 10 minutes of consecutive failures. Every error that leaves the loop (give-up, non-retryable, no `status`, Ctrl-C) carries `task_id`, the `idempotency_key` when known, and a fix ending in the resume command. Fix and usage texts show the command that actually runs (`node <path to main.ts>`, from `process.argv[1]`). Numbers must match `^\d+(\.\d+)?$` before `Number`, so hex and exponent forms are rejected. `signup` prints the key before saving; a save failure is a `config_error` whose fix says to set `EYES_API_KEY`.

## Decisions & alternatives rejected
- Agent card follows A2A 1.0 (orchestrator ruling, round 1): no top-level `url`; `/mcp` and `/` live in `supportedInterfaces` with custom binding URIs (MCP Streamable HTTP spec, OpenAPI 3.1 spec), because Eyes does not speak A2A JSON-RPC or HTTP+JSON.
- `/w/*` worker routes are left out of openapi.json (orchestrator ruling): agents never call them.
- Local validation reuses the zod contracts instead of hand-written bounds, so the CLI cannot drift from the server limits.
- CLI-only error codes `network_error`, `unexpected_response`, `config_error` and `interrupted` sit next to the server catalog codes so `--json` callers can tell a retryable transport failure from a bad server reply. Round 2: inside the wait loop any HTTP status >= 500 is retried, because a gateway 502/503/504 must not end the loop and invite a second `ask`; a 200 without `status` and 4xx replies still stop at once, and the 10-minute bound stops a dead server from looping forever.
- Retry notices go to stderr (JSON in `--json` mode), so stdout stays one result object per line.
- The freshness test compares parsed JSON for the JSON files and exact text for llms-full.txt; Biome owns JSON formatting.
- Tool summaries live once in `TOOL_DOCS` (typed by `ToolName`) and feed OpenAPI, llms-full and agent card skills. llms-full drops `pattern` where `format` is present to save tokens.

## Assumptions
- REST semantics from PR #2 (`apps/mcp/src/server.ts` on feat/T1.1-mcp): JSON bodies, `task_id` in the path, `/await` body `{timeout_seconds?}`, `/dispute` body `{reason}`, error bodies from `EyesError.toBody()`, MCP schema mismatches as "Input validation error" text, docs read from `docs/public/<path>`.
- Statuses from the T1.2 engine branch: answered = verified, paid, needs_review; final = expired, refunded, disputed. `refunded` is set by cancel, `expired` by the deadline sweep; both refund bounty and fee.
- `SignupOutput.email_address` and the `LocationInput` description come from ADR-007; the `timeout_seconds` description from ADR-008.
- The engine always fills `top_up_url` (signup, balance, `insufficient_balance`), so the docs no longer describe a null case.
