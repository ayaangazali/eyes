## Why
An agent that has never heard of Eyes must get from "here is a URL" to a verified answer using only public docs: sign up, hand the top-up link to its human, connect MCP, then quote, ask and loop on await. These are the files apps/mcp serves at `/llms.txt`, `/llms-full.txt`, `/openapi.json` and `/.well-known/agent-card.json`, plus a CLI so the same capabilities work from a shell (§9).

## What
- `docs/public/llms.txt` (hand-written, 87 lines, llmstxt.org shape): scope (public places only), pricing, escrow and refunds, the 4-step quickstart with the exact `claude mcp add` command and a generic JSON config, every status including `needs_review`, errors with `fix`, links.
- `cli/src/docs.ts` generates `openapi.json` (OpenAPI 3.1, every `HTTP_ROUTES` entry except health, webhooks and the two browser redirects; schemas from the zod contracts via `z.toJSONSchema`; bearer scheme; `Error` with `error`, `message`, `fix`), `llms-full.txt` (llms.txt plus signup, per-tool REST route, summary, example and input/output JSON Schema, and the `ERRORS` catalog) and `.well-known/agent-card.json`. `pnpm --filter @eyes/cli gen:docs` writes them, then Biome formats the JSON.
- `cli/src/main.ts`: `eyes signup|ask|quote|status|cancel|dispute|balance|policy` with `node:util` parseArgs, `--json`, config at `~/.config/eyes/config.json` (0600) with `EYES_API_URL`/`EYES_API_KEY` overriding it. `ask` sends a random UUID `idempotency_key` and loops `POST /v1/tasks/:id/await` until `answered` or status `expired|refunded|disputed`.

## Decisions & alternatives rejected
- Agent card follows A2A 1.0 (a2a.proto on a2aproject/A2A main, fetched 2026-10-17). It has no top-level `url`, so the task card's url `"/"` goes into `supportedInterfaces` next to `/mcp`. Eyes does not speak A2A JSON-RPC, so both interfaces use custom binding URIs (MCP Streamable HTTP spec, OpenAPI 3.1 spec) instead of claiming `JSONRPC` or `HTTP+JSON`.
- `/mcp`, the worker routes and the doc routes are in the OpenAPI. They are REST-shaped `HTTP_ROUTES` entries outside the exclusion list; worker routes are tagged `worker` and say agents never call them.
- Errors use `4XX` and `5XX` responses instead of `default`, so Redocly's 4xx rule passes and the status list per code is in the response description.
- The freshness test compares parsed JSON for the two JSON files and exact text for llms-full.txt, so Biome owns JSON formatting and the test owns content.
- Tool summaries live once in `TOOL_DOCS` (typed by `ToolName`, so a new tool fails typecheck) and feed OpenAPI descriptions, llms-full and agent card skills. The richer MCP descriptions stay in apps/mcp, which this task may not edit.
- llms-full drops `pattern` where a `format` is present (uuid, date-time) to save tokens; openapi.json keeps the exact schemas.

## Assumptions
- REST semantics read from PR #2 (`apps/mcp/src/server.ts` on feat/T1.1-mcp): JSON bodies, `task_id` in the path, `/await` body `{timeout_seconds?}`, `/dispute` body `{reason}`, error bodies from `EyesError.toBody()`, docs read from `docs/public/<path>`.
- Answered and final statuses read from PR for T1.2 (`packages/engine/src/index.ts`): answered = verified, paid, needs_review; final = expired, refunded, disputed.
- `.mcp.json` header and `claude mcp add` syntax from docs/vendor/mcp-use-manufact.md.

## Known gaps
- URLs in the docs are relative because the public origin is unknown. Once it is known, apps/mcp could rewrite them to absolute at serve time (A2A and some scanners prefer absolute).
- The CLI is not published to npm; agents run it from the repo. `eyes ask` makes a new idempotency key per run, so re-running after a network error can create a second task.
- No `/agents.md`, `robots.txt` or sitemap yet (Armature scanner cheap wins); they belong to T3.4 or a follow-up.
