## Why
- The ops dashboard logged `Error: unsupported Unicode escape sequence` twice at 07:49:13Z and 07:49:14Z on Oct 18. The persisted event log shows both were `POST /v1/tasks` from a QA agent: `askEyes` called `eyes_post_task` (engine index.ts:706), the ask contained a NUL character, InsForge rejected the JSON body, and the agent got a 500. Postgres text and jsonb can't store `\u0000` (and jsonb rejects unpaired surrogate escapes), so any caller passing such a string would fail the same way.
- The ops errors list also showed `owner email for agent … failed: PrimitiveApiError status 403 … not a Primitive-managed recipient domain`. Smoke and test agents sign up with example.com and other reserved names, which never reach a mailbox.

## What changed
- `pgSafe()` in `packages/db/src/rpc.ts` runs over every RPC's args in `createRpc` (Postgres and InsForge). It goes through nested objects, arrays and keys: NUL is removed, lone surrogates become U+FFFD, everything else (numbers, null, Dates, other strings) is unchanged. Every DB write goes through `createRpc`; storage uploads are binary and don't touch Postgres text.
- `emailOwner` (owner and first-payer emails) skips RFC 2606/6761 reserved domains (example.com/.org/.net and subdomains, `.example`, `.test`, `.invalid`, `.localhost`, `localhost`) with a `console.debug` line. Debug isn't captured into the ops event log. A provider error with status 403 whose message mentions the recipient is logged with `console.warn` and a plain message; other failures stay `console.error`. Signup still succeeds either way and tells the agent the email wasn't sent.

## Tests
- `packages/db/src/rpc.test.ts`: `pgSafe` on nested values, keys, lone surrogates and Date identity; the InsForge request body is cleaned.
- `packages/db/src/rpc.int.test.ts`: real local Postgres: a text arg with NUL (`eyes_join_worker`), `eyes_append_ticket` with NUL, and a jsonb arg with NUL (`eyes_record_pings`) all succeed and store the cleaned value. Before the fix this test failed with `invalid byte sequence for encoding "UTF8": 0x00`.
- `packages/engine/src/engine.int.test.ts`: six reserved domains are skipped at debug level with no send; a 403 recipient denial is one warning and no error. Owner and payer fixtures that expect a send moved off example.com.

## Verification
- See the commit message for test counts. After the deploy, the persisted event log shows no new `unsupported Unicode escape sequence`.

## Known gaps
- The ops event log keeps no user agent or client country, so who sends an API request can only be traced by agent id and name.
