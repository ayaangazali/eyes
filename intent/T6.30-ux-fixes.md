## Why
The landing page said "The agent disputes it." for a fake answer. A person (the agent's owner or a reviewer) disputes a wrong answer, not the AI. The same claim was in `docs/SPEC.md` and `docs/SUBMISSION.md`.

A UX review of the worker pages and the API's `/status` page (screenshots in /tmp/ux-review) found dead ends: a failed capture link left empty clock and pin rows, a two-column error card and no way forward; /app and /here without a code only said what to text; the join form gave no clear confirmation after locating; tap targets under 44px; /status led with vendor names and showed "not recorded".

## What changed in this batch
- `apps/web/landing/src/pages/index.astro`: the "If an answer is fake" line now says "A human disputes it." Docs say "a human disputes wrong answers". The SQL comment in `packages/db/migrations/021_disputes.sql` is unchanged (it describes the API call; migrations are frozen).
- Capture error: empty bounty, clock and pin rows are hidden by CSS `:empty` rules; a primary `sms:` button "Text TASK for a new link". `packages/ui`: a `.ui-notice` without an icon is a block, so every script-filled error notice is one column.
- TASK keyword (ADR-027): `task`/`link` reply intent; the engine texts the capture link of the worker's open claim (claimed, deadline in the future), else "You have no open task right now. We'll text you when one is near." HELP mentions TASK. INSTALL without a TestFlight link says "The Eyes app is in Apple's review. Text HERE to share your spot meanwhile."
- /app: "Install / open Eyes app" opens `eyes://connect#c=<code>`; after 2.5 s of the page visible and focused it goes to `VITE_TESTFLIGHT_URL`, or, while that is unset, to the ad hoc install page `/install#c=<code>` (same code, still only in the fragment). `visibilitychange` (hidden) and `pagehide` cancel the fallback. `blur` pauses the clock and `focus` resumes it with the time left, because iOS's "Open in Eyes?" prompt and its "cannot open" alert both blur the page. Logic in `openApp()` (`app-link.ts`).
- /app and /here without a code: primary `sms:` buttons with APP / HERE prefilled (`smsHref()` in `api.ts`).
- Join: "✓ Location set" on the button after a fix, accuracy in the hint; fine print 13px; the privacy link has a 44px tap area. /automation copy buttons are full size (44px). The shared `:focus-visible` ring already existed in `packages/ui/components.css`.
- /status: plain names first (Texting, Email, Payments, Photos, Photo moderation, Place lookup, Safety check, Database) with the vendor in grey; a status dot on every row (aria-hidden, the text states the state); no commit row when `EYES_COMMIT` is unset.
- Landing "four moves" (#3): on wide screens the pin lasts 1.25 screens instead of 2.5 (about 225 px per state at 900 px tall), so every scroll step changes the panel; the page is 1,125 px shorter at 1440. Below 768 px there is no pin and no dimming: all four steps and the finished panel show as they are.
- Landing contrast (#6): inactive steps use `--eyes-text-secondary` for the title instead of 45% opacity, step numbers use the secondary token instead of tertiary, and the photo card no longer fades from 30% opacity (it scales and locks only), so its text is always solid surface + text tokens.
- Landing hero (#9): the left column is vertically centred against the photo; the header CTA says "Earn as a worker".
- One site header (#7): `siteHeader()` in `packages/ui/header.ts` with `.ui-site-head` CSS in `components.css`, used by the landing, the worker web and the API pages (`page.ts`). Same 4rem height and padding; the inner row is `--ui-column` wide so the wordmark starts where each page's text starts (landing 72rem, landing terms/privacy 68ch, worker 36.5rem or 72rem for wide pages, API 40rem). The bracket mark is one `.ui-mark` rule. h1 uses `--eyes-font-display` (Instrument Sans): the worker web bundles `@fontsource-variable/instrument-sans`; the API serves the woff2 at `/fonts/instrument-sans.woff2` (immutable) and the page CSPs allow `font-src 'self'`.
- Motion and polish (Emil Kowalski's design-engineering rules), shared in `packages/ui` so the landing, worker web and API pages behave the same: tokens `--eyes-ease-out` (0.23, 1, 0.32, 1), `--eyes-ease-in-out`, `--eyes-duration-press` 160ms, `--eyes-duration-enter` 200ms, `--eyes-press-scale` 0.97, `--eyes-enter-y` 6px. Buttons transition exact properties (colour with `ease`, transform with the strong ease-out) and scale to 0.97 on `:active` (not when disabled); hover styles only under `(hover: hover) and (pointer: fine)` (buttons, links, inputs, the landing's accent ring and marquee pause). Notices rise 6px and fade in over 200ms with `@starting-style` when shown; hiding stays instant (exit faster than entry); the action under a notice follows 50ms later. The join location button has three states: busy (`aria-busy`, a 0.6s spinner replaces the icon, label kept), located ("✓ Location set" resolves from a 2px blur, `data-settled`), failed ("Try location again" and the error notice rising in). The spinner turns in 0.6s instead of 0.8s. Reduced motion keeps colour and opacity changes and sets the press scale to 1 and the rise to 0 (it used to drop every transition). The landing badge swap uses the strong ease-out. Focus rings stay instant (keyboard actions are never animated).
- Ops header (internal.eyes.pictures): the "Eyes ops" logo was a local `.mark` rule that drew a solid yellow square; it now uses the shared `.ui-mark` viewfinder from `@eyes/ui` (components.css is already inlined into ops.html, so no new script, file or CSP change). `apps/web/dashboard/src/server.test.ts` checks the header uses `ui-mark` and the local rule is gone.
