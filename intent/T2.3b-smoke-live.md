## Why
`.github/workflows/live-smoke.yml` runs `pnpm run --if-present smoke:live`, and no such script existed, so the workflow passed while checking nothing. As each vendor key lands (docs/PLAN.md §4) the orchestrator needs one command that proves the deployed server works and says exactly which providers are live.

## What
- `scripts/smoke-live.ts`, run with `pnpm smoke:live` against `EYES_PUBLIC_API_URL` (exit 2 with a message if unset). Each check prints PASS, FAIL or SKIP with its time; exit 0 only when nothing FAILs.
  1. `GET /healthz`: provider map and db kind as a table.
  2. `/llms.txt`, `/openapi.json`, `/.well-known/agent-card.json` return 200 (JSON ones must parse); a 404 is SKIP because the docs are not on main yet (PR #9).
  3. Auth: `EYES_SMOKE_API_KEY`, else `POST /v1/signup` as `smoke-<iso time>`; then `GET /v1/balance` and `GET /v1/spend-policy`.
  4. MCP over streamable HTTP with the bearer key: `tools/list` must equal `Object.keys(TOOLS)` from `@eyes/core`; `get_balance`; `quote_task` for "Ferry Building, San Francisco", `is_open`.
  5. Unsigned `POST /webhooks/{inkbox,stripe,primitive}` with `{}` must be 4xx.
  6. Only with `SMOKE_ASK=1`: `ask_eyes` (bounty 1 USD, unique idempotency_key), `cancel_task`, then balance and escrow must equal their starting values.
- `redact()` hides `eyes_test_`/`eyes_live_` keys, `ask+...@` email capability addresses, `<body>.<mac>` link tokens (ADR-009 shape) and any key it was handed, on every printed line.
- Root `package.json`: `"smoke:live": "node scripts/smoke-live.ts"` (allowed exception for this task).

## Decisions & alternatives rejected
- Tool names come from `TOOLS`, not a hard-coded list, so a contract change cannot leave the smoke stale.
- Webhooks pass only on 4xx. A 5xx (for example live Stripe with no webhook secret) is a FAIL, because it means the server cannot verify that vendor's events.
- `ask_eyes` uses the 1 USD minimum bounty so a forgotten cancel strands the least money, and the FAIL message names the task_id if the cancel does not happen.
- Every fetch has a 15 s timeout: a dead deploy should FAIL, not hang the workflow.

## Assumptions
- `@modelcontextprotocol/client` 2.3.1: `new StreamableHTTPClientTransport(url, { requestInit: { headers } })` sends the bearer header on every request (read from `dist/index.d.mts`, same pattern as `e2e/golden-path.spec.ts`).
- `import.meta.main` guards the run so the unit test can import `redact`; CI uses Node 24 latest, which has it.

## Known gaps
- Each run without `EYES_SMOKE_API_KEY` signs up a new agent, which gets the 20 USD test grant on a test-mode server. Set `EYES_SMOKE_API_KEY` as a repo secret to reuse one agent.
- The deployed server stays red on `quote_task` until PR #7 (T1.5 safety) merges and redeploys; the docs checks stay SKIP until PR #9 merges.
- `SMOKE_ASK=1` cannot settle a task a worker claims before the cancel lands; the FAIL names the task_id so a human can follow up.
