## Why
The Eyes iOS app (T6.16) needs a per-worker location code. Pasting a code from a text is the step workers drop. One tap from the text should open the app already connected.

## What
- New reply intent APP (text "APP"). SHORTCUT and AUTO are unchanged.
- START (opt in) now also texts, as a second text after the welcome: "Get the Eyes app so tasks find you: https://app.eyes.pictures/app#c=<code>". APP texts the same line on its own. Each mints a code through `eyes_rotate_location_token` (adds a code; the 5 newest work), the same path as SHORTCUT.
- No churn: a START within an hour of the last app link sends only the welcome, no new code. APP always mints. STOP (which deletes every code) resets the hour, so the next START sends a fresh link.
- HELP mentions APP.
- Worker web `/app` (`app.astro`, noindex): reads `c` from `location.hash`, clears the fragment from the address bar with `history.replaceState`, shows "Open in the Eyes app" linking to `eyes://connect#c=<code>` and tries to open it on load, plus "Don't have the app yet? Ask the Eyes team for an invite (TestFlight coming)". With no code it says to text APP. The page sends the code nowhere.

## Decisions & alternatives rejected
- The code goes in the URL fragment, not the query: browsers do not send fragments to servers, so neither Cloudflare nor any server log sees it, and it is not in a Referer.
- Inkbox: links are not allowed in a cold first iMessage, but START and APP are replies from the worker, so a link is allowed (docs/vendor/inkbox.md).
- Known ceiling: the "last app link" time is kept in memory (one server instance); a restart allows one extra code on the next START. A column would need a migration.

## Verification
- `packages/engine/src/location.int.test.ts`: START texts the app link with a 43-character code in the fragment that works as a location code; START again within the hour sends only the welcome and no new code; APP mints a second code as one text; an hour later START mints again; after STOP, START sends a fresh link.
- `packages/comms/src/inkbox.test.ts`: "APP" and "app" parse as the app intent.
- `apps/web/worker/e2e/app.spec.ts` (Playwright): the button href is `eyes://connect#c=<code>`, the address bar has no fragment afterwards, no request carries the code, the page is noindex; without a code it says to text APP.
- Tests that read the payout link as the last text after START now look for the welcome text (START sends two texts now). `pnpm test:integration` 114/114 on local Postgres.
