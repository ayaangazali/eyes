## Why
The shift Shortcut only runs while the worker keeps it going. A small app with "Always" location keeps the worker's spot fresh with the app closed, so tasks reach workers near them.

## What
- `apps/mobile`: Expo SDK 58 (React Native 0.88), iOS only, bundle id `pictures.eyes.worker`. One screen: set up by link or paste (43-char base64url code, stored in the keychain via expo-secure-store, readable after first unlock so background wakes can send), allow location (foreground then "Always", or Open Settings when denied), then status: sharing toggle, last automatic send time and result, approximate place (2 decimals), Remove code. No send button: sending is automatic.
- Setup link: scheme `eyes`. `eyes://connect#c=<code>` (code in the fragment; `?c=` also accepted) opens the app on cold start or while running, saves the code (replacing any saved one, clearing the last result), shows "Connected" and goes straight to the location step. The server side (texted `https://app.eyes.pictures/app#c=<code>` page that opens this link) is built separately. The paste screen stays as a fallback: "Text APP to Eyes to get your link."
- Background: `Location.startLocationUpdatesAsync` with a TaskManager task (Balanced, 300 m, 5 min deferral, pauses automatically, activity Other, no blue pill). expo-location also starts significant-change monitoring for the same task, and expo-task-manager re-registers the task when iOS relaunches a terminated app for a location event, so updates resume after the app is killed by the system (not after a user force-quit: iOS rule).
- Sends: the background task posts the latest fix to `POST /w/location` with `source: "app"` (migration 020, T6.15). While sharing is on, the app also sends one fix right after setup (code saved and "Always" granted) and each time it comes to the foreground. Every send is skipped when the last success was under 60 s ago or another send is in flight (the task and the foreground share one JS runtime). 401: stop updates, delete the code, show "Code stopped working: text AUTO to Eyes for a new one". 429 is not an error: the server stored a fix for this worker seconds ago (1 per 30 s), so the app shows "Up to date" with the last success time and retries silently on the next update.

## Decisions & alternatives rejected
- npm inside `apps/mobile` with its own `package-lock.json`, excluded from the pnpm workspace (`!apps/mobile`): Metro and CocoaPods autolinking expect a flat `node_modules`; pnpm's symlinked layout needs `node-linker=hoisted` for the whole repo, which would change every other package.
- The root `tsconfig.json` excludes `apps/mobile` (React Native and DOM globals clash with the Node types); `apps/mobile/tsconfig.json` is strict and is run with `npm run typecheck` there. Biome and the root vitest `unit` project still cover `apps/mobile` (the send logic in `src/eyes.ts` has no Expo imports).
- No navigation library, no AsyncStorage: one screen; the small last-result record sits in the keychain next to the code.
- A fix that arrives within 60 s of the last post is dropped, not queued (no timers in a background wake). In the background the 5 min deferral makes that rare; in the foreground the next move or the next return to the app covers it.
- No `shortcut` fallback for `source`: 020 was live in production before this shipped.
- vitest over jest-expo: the tested logic is plain TypeScript and the repo already runs vitest.

## Verification
- `apps/mobile/src/eyes.test.ts`: code format, setup-link parsing (fragment and query, wrong host or malformed code rejected), status mapping, one `app` POST, 60 s throttle, 401 stops and saves a rounded place, no code stops without posting.
- iOS Simulator (iPhone 17, iOS 26.5), Release build, with a test code minted for the operator's own worker: after Save the background task posted on its own (worker row `location_source` = `app`, `location_at` updated); a send 15 s later got 429 (then labelled "Too many updates", now "Up to date"); a send after moving the simulated location showed "Sent" and the worker row moved to 37.76, -122.39. After the test code was revoked, the next send got 401: the app stopped, deleted the code and showed "Code stopped working". Test code deleted from the database and from disk. (These runs used the since-removed Send now button.)
- Setup link on the Simulator: `xcrun simctl openurl` with `eyes://connect#c=<fresh test code>` opened the app showing "Connected" and "Sharing your location"; the code's `last_used_at` and the worker row's `location_at` updated within a second.
- `pnpm verify:fast` green.
