## Why
Live mode needed `ANTHROPIC_API_KEY` for two decisions: the safety classifier and the photo check. Both are classification, and Claude is the slow step on the demo path. Cloudflare's `clef-omni` is a decision model: it takes a state plus typed questions (and images) and returns a probability per option in about 0.2 s. Using it first makes the common case fast and lets the server go live without an Anthropic key. For the demo no review queue or extra fraud handling is built: unsure cases go to Claude when it is configured, otherwise they fail closed.

## What
- `packages/safety`: with `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN`, the rules run first, then one clef `choice` question over `allowed` plus the 8 safety categories. P(allowed) >= 0.9 allows, <= 0.2 blocks with the most likely category, anything between is unsure. Unsure or a clef error goes to the existing Claude classifier when `ANTHROPIC_API_KEY` is set. Without Claude, unsure is refused (`UNSURE`, nothing charged) and a clef error is `UNAVAILABLE`. Claude-only behavior is unchanged.
- `packages/verify`: `createClefVision` downloads the photo (clef takes no URLs), asks two `noul` questions (answers the question, prominent faces) and trusts the answer when both are at least 0.3 from 0.5. Otherwise, or on error, it uses Claude when configured; without Claude it returns `answers_question: false`, so the task lands in the existing `needs_review` queue with escrow held.
- `apps/mcp`: live mode starts with either clef credentials or `ANTHROPIC_API_KEY`; vision uses clef when its credentials are set; `/status` counts clef as the AI classifier.

## Decisions & alternatives rejected
- Thresholds, not clef's own `choice`: the argmax alone wrongly allowed 3 block fixtures. Recall on block fixtures is the hard constraint.
- A `noul` "is this allowed" question was measured too and was worse (1 block fixture allowed even at 0.9, about 2x more unsure).
- No queue for unsure tasks: out of scope for the demo. Safety refuses them; photos reuse `needs_review`.

## Assumptions
- Clef probabilities on new phrasings behave like on the fixtures. The cut-offs carry a `ponytail:` note to re-run the calibration when the prompt or model changes.
- The photo band (0.8 / 0.2) has not been measured on real worker photos.

## Verification
- Calibration (scratch script, not committed), 200 fixtures, 156 reach the classifier after the rules: at 0.9 / 0.2, 0 block fixtures allowed, 2 allow fixtures blocked ("Make sure the license plate of a car isn't readable in the photo.", "Don't photograph someone's car or license plate."), 53 unsure. p50 190 ms, p95 348 ms.
- `pnpm safety:eval` with clef credentials and no Anthropic key (2026-10-17): recall 1.000, precision 0.697. 46 allow fixtures refused: 44 unsure (mostly "don't photograph faces / plates / follow" phrasings) and the 2 plate instructions above. With `ANTHROPIC_API_KEY` set those 44 go to Claude instead.
- Unit tests: clef allow, clef block with category, unsure to Claude, unsure refused without Claude, clef error fails closed; clef vision sure verdict and unsure to review.
- live-verified: no.
