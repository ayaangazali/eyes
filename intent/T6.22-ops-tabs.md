## Why
/ops was one long page of small fixed-height boxes; the tickets and queue lists will grow with disputes.

## What
- A tab bar under the sticky header: Overview (health, 24 h tasks, money summary, trends), Review (needs_review / disputed queue, count in the tab), Support (tickets, open count in the tab), Tasks, Workers (map + list), Money (ledger), Logs (server errors + event log, count in the tab).
- The URL hash picks the tab (`/ops#support`), so a reload or a shared link keeps it.
- List tabs use the viewport height; only the list scrolls.
- Support: search (question, message, task id, ticket id, place), Open / Resolved / All, 50 at a time with Show more. Tasks: status filter. Money: ledger type filter. Workers list shows a short id and state, no coordinates.
- ARIA tablist: role tab / tabpanel, aria-selected, roving tabindex, arrow keys, Home and End. At 390 px the tab bar scrolls sideways.
- Element ids that matched a tab name (`review`, `tasks`, `workers`, `money`) were renamed so the hash never scrolls to them.

## Decisions & alternatives rejected
- Client-side filtering and paging over what the feeds already return: no new endpoints.
- The Leaflet map is built while hidden; opening Workers calls `invalidateSize` and refits.

## Verification
- Playwright against live data with this file served in place of /ops: all 7 tabs at 1440x900 and 390x844, light and dark, no page errors.
