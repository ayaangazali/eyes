## Why
Builders work in parallel on disjoint files, so everything they share must be fixed first: tool schemas, the error catalog, provider interfaces with fakes, the `EyesService` seam, the route factory signatures and the database schema. After G0 these change only by ADR.

## What
- `packages/core`: zod schemas for domain rows, all eight tool inputs and outputs (`TOOLS`), worker HTTP payloads, `HTTP_ROUTES`; `ERRORS` catalog and `EyesError` with templated `fix`; provider interfaces (`Messaging`, `Email`, `Payments`, `Storage`, `Vision`, `Geo`, `Clock`) and fakes; `EyesService`, `EngineDeps`, `AppConfig`, `AssessTask`, `VerifySubmission`, `RouteDeps`; cents, haversine distance and HMAC link tokens.
- `packages/db`: `001_init.sql` (agents, workers, tasks, offers, submissions, ledger) and an idempotent `migrate()`.
- Seams: `createEyesService`, `createInkboxMessaging`, `inkboxRoutes`, `createPrimitiveEmail`, `primitiveRoutes`, `createStripePayments`, `stripeRoutes`, `verifySubmission`, `createClaudeVision`, `createAssessTask`. Each throws or answers `not_implemented` until its task lands.

## Decisions & alternatives rejected
- Messaging is semantic (`sendOffer`, `sendCaptureLink`) so comms owns wording and iMessage limits while the engine owns flow (ADR-004).
- Additions beyond the spec, each for agent experience: `resolved_location` on quotes, `deadline_at` and `next_step` on ask/await outputs, `escrowed_usd` on balance.
- Database invariants enforce money safety: unique `(task_id, type)` on ledger, non-negative balance, unique `(agent_id, idempotency_key)` (ADR-001).
- No in-memory database fake: integration tests use real Postgres (ADR-003).

## Assumptions
- InsForge offers no direct Postgres URL, so production uses RPC over HTTP (docs/vendor/insforge.md).

## Verification
- `pnpm test:contract`: 10 passed (schema snapshot, defaults, await cap, error catalog completeness and rendering, no leak of unknown errors, cents, distance, token tamper and expiry, fake payment idempotency).
- `pnpm test:integration` on Postgres 17: 4 passed (idempotency key unique, ledger once per task so no double release, balance never negative, two concurrent conditional claims produce exactly one winner).
