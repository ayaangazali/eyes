## Why
The second security sweep found three minors on main. The public pages (`/`, `/status`, `/topup/done`, `/topup/cancel`, `/w/connect/done`) and the error pages behind the `t:` and `c:` links sent no CSP, Referrer-Policy or Cache-Control, while the owner, earnings and ops pages did. `POST /w/join` echoed the internal worker id for any phone that had already joined. The hosted ops feed (`/ops/<key>/feed`, #67) served worker positions to the metre, which the loopback-only dashboard had been fine with.

## What
- packages/payments: `OWNER_HEADERS` is now the exported `PAGE_HEADERS` (same values). The middleware that applied it to `/owner/*` and `/w/earnings/*` now also covers `/topup/*` and `/w/connect/*`, so the top-up done and cancel pages, the payout-setup done page, and the error pages and redirects behind `t:` and `c:` links all get no-store, no-referrer and the same CSP.
- apps/mcp: `/` and `/status` send `PAGE_HEADERS`. JSON routes are unchanged.
- `JoinWorkerOutput` drops `worker_id` (ADR-021). `joinWorker` returns the same body for a new phone and a known one. A repeat join still changes nothing.
- `/ops/<key>/feed` rounds each worker's `lat` and `lng` to 3 decimals (about 110 m) before sending them. Tasks, photo URLs, ledger and totals are unchanged. The loopback dashboard's `/feed` still sends full precision, and `eyes_dashboard_feed` (004) is untouched.

## Decisions & alternatives rejected
- Reused the payments header middleware and its constant instead of writing a third header set. Its CSP (`default-src 'none'; style-src 'unsafe-inline'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`) fits every one of these pages: inline styles only, no scripts, no images, and no forms except the owner console's same-origin posts. The ops page keeps its own CSP for Leaflet.
- no-store on `/` and `/status` too, though each is rendered once per boot: they show which providers are live and the deployed commit, both of which a redeploy changes. They send no validators, so browsers do not cache them today anyway, and one header set is simpler than two.
- No catch-all "any text/html" middleware: mcp-use can serve its own landing page for `/mcp`, with scripts, Google Fonts and images, and a blanket strict CSP would break it. Listing the page routes covers every HTML response Eyes renders.
- Worker coordinates are rounded in the hosted route only. The judge's split: tasks are public places, so their pins stay exact for the demo; workers are people. The 004 function stays as it is because the loopback dashboard reads it too.
- Join oracle: drop the field, not a random id for known phones, and no migration (ADR-021).

## Assumptions
- Browsers apply a redirect's Referrer-Policy to the next request, so the 302s to Stripe Checkout and Connect onboarding now send no Referer. Stripe needs none.
