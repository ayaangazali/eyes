## Why
Judges get about two minutes with the repo and then decide whether to look further, so the README has to say what Eyes is, prove how it works and show honestly what is live. The submission form and the live demo are due at the same hour (10:00 AM Sunday), so the submission text and the presenter's runbook are written now, with slots for facts that only exist after the keys land.

## What
- `README.md`: pitch, 5-step flow with a mermaid sequence diagram, agent quickstart (MCP URL, signup curl, `claude mcp add`, the 8 tools, an ask/await exchange, an error with its fix), worker JOIN, owner controls, safety, money, sponsor table, architecture and repo map, how the repo was built, local development.
- `docs/SUBMISSION.md`: form text with one case per sponsor track grounded in the code, what's next, team; TODO slots for videos, live facts and the pre-event work disclosure.
- `docs/DEMO.md`: pre-demo checklist with commands and pass criteria, the 90-second script with exact prompts and what to point at per sponsor, fallbacks per beat, reset steps.

## Decisions & alternatives rejected
- Live claims come only from STATUS.md "Live verification" (Manufact partial, InsForge yes, everything else no). The README says up front that the deployed server runs vendors as fakes, because a judge who tries `ask_eyes` today gets `no_workers_nearby` and should know why.
- Unmerged work (agent docs and CLI, #9) is linked by PR and marked in review, never described as shipped; repo-relative links point only at files on main. Round 2: #26 (smoke:live) and #35 (owner console, ADR-011) merged, so they are plain links and commands now.
- The README error example is the real `unsafe_task` body (rule-layer `private_residence` reason and fix from `packages/safety/src/rules.ts`); the ask/await example uses real field names with values marked illustrative.
- Demo prompt 2 says "do not retry": the `bounty_exceeds_max` fix tells the agent to lower the bounty, and Claude following it would post a real $2 task mid-demo. Prompt 3 keeps the city because the engine geocodes before the safety check, so an unresolvable address returns `location_not_found` instead of the refusal.
- SPEC §13 beat 4 shows a Stripe top-up, but the test-mode signup grant is an Eyes ledger row with no Stripe object, so the runbook tops the demo agent up once through `top_up_url` before the demo and labels `escrowed_usd` as Eyes ledger escrow, not Stripe.
- The runbook keeps the API key, the agent email address and the owner link off screen: each is a capability and per-link revocation does not exist yet (#28).
- Rejected: a separate video script file. PLAN §3 lists it, but the script table in DEMO.md is what the video records.
