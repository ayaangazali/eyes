## Why
Every PR ran the full suite, including e2e and the web build, even for docs-only or single-package changes. Pushes to main, the nightly run, and manual runs still run everything.

## What changed
- `scripts/ci-scope.ts`: reads the PR's changed files and prints `full`, `changed`, `coverage_mode`, `coverage_include`, `e2e_worker`, `e2e_golden`, `web`, and `reason`. Also writes them to `GITHUB_OUTPUT`. `--full` skips git (used for pushes, the nightly, and manual runs). A base that cannot be diffed fails the job instead of skipping checks.
- Full-run triggers: `vitest.config.ts`, `package.json`, `pnpm-lock.yaml`, `.github/**`, `packages/core/**`, and the scope script itself.
- `.github/workflows/ci.yml`: new `scope` job. On PRs, unit, contract, integration, and safety run `vitest --changed origin/<base>`. Coverage measures only the changed source files (`COVERAGE_GATE=1`). Worker e2e runs for `apps/web/**` and `packages/ui/**`. Golden-path e2e runs for `e2e/**`, `apps/mcp/**`, and `packages/**`. The web build runs for `apps/web/**` and `packages/ui/**`. Lint, typecheck, intent, secrets scan, and `ax:eval` run on every PR, as before. Added a nightly `schedule` and `workflow_dispatch`. Job names are unchanged, so required checks keep their names.

## Known gap
- The web build runs only for `apps/web/**` and `packages/ui/**`. A change in another package that the web app imports skips the PR build. Full runs on main and the nightly still build everything.
