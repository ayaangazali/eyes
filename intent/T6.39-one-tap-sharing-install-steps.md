## Why
Operator feedback: workers got lost on the install page, and in the app, tapping Allow on location did not start sharing. Sharing waited for "Always", so a worker who kept "While Using" ended on an Open Settings blocker.

## Taps from "app opened by the connect link" to "sharing"
- Before: 3. Tap "Allow location", then "Allow While Using App", then "Change to Always Allow". "Keep Only While Using" stopped there with no sharing.
- After: 1. Tap "Allow While Using App". Sharing starts and the first fix is sent. The Always prompt follows as an optional second tap. Declining it keeps sharing and shows one inline Settings line.
- iOS's "Open in Eyes?" prompt for the link is the same before and after.

## What changed
- `settle()` in `apps/mobile/src/eyes.ts` replaces `permOf`. It is one pass shared by launch, deep link, return from Settings and the buttons:
  1. code, then paused flag.
  2. Ask While Using right away (no button).
  3. Start location updates (expo-location needs foreground permission only).
  4. Show "Sharing" and send the first fix.
  5. Ask Always once per launch. iOS shows that upgrade prompt once; later asks resolve with no dialog.
- App screens:
  - Paste code (no link).
  - Allow location (only when a dialog was dismissed).
  - Open Settings (denied).
  - Sharing, with a small "Stop sharing" link.
  - "Sharing is off" with "Share again".
- Removed: the Switch, "Remove code", the "Allow location" button step and the "Connected" label.
- "Stop sharing" is stored (`paused` in SecureStore), so it survives launches. A new code clears it.
- A failed code save falls back to the paste screen instead of a blank one.
- `EXPO_PUBLIC_EYES_API` overrides the API host for dev builds only (simulator proof against a local server). Releases leave it unset.
- Version 1.0.1, build 2.
- Install page: four step cards (Register, Install, Developer Mode, Open Eyes).
  - The current step has the accent ring. Done steps fold to their title.
  - Each step draws the iOS alert it triggers, with the button to tap filled, and has a "Didn't work?" disclosure.
  - Step 4 has "Open Eyes" (`eyes://connect#c=<code>`), so the app connects without the text.
- The page keeps `{code, savedAt}` in localStorage, so the code survives the profile round trip through Settings and the Developer Mode restart. Limits:
  - It expires after 24 hours.
  - A 401 removes it.
  - Eyes opening from "Open Eyes" (the page goes hidden) removes it.
  - It is only sent as the Bearer header of `/w/device`.
- Tapping Install records `installed`, so the next visit starts at Developer Mode.
- The ad hoc release text "Eyes is ready" carries `/install#c=<fresh code>` (minted as the engine does: random 32 bytes, only the sha256 stored). The text is shortened to `<api>/s/<id>` by `withShortLinks` from T6.38.
