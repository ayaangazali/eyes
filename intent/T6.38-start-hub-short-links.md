## Why
The operator's phone showed START as 2-3 bubbles of ~200-character signed links, and asked workers to remember START, STOP, YES, NO, HELP, HERE, APP, AUTO, SHORTCUT, INSTALL, TASK. A typo ("Strat") got "Sorry, we did not get that".

## What changed in this batch
- START sends one text: "You're in. Eyes texts you paid photo tasks near you." then numbered steps (get the app, only once an hour; update your spot, only when stale; set up payouts, only while not set up, or the simulated-pay note on a test server), "Your setup: <me>", "When a task comes, reply YES to take it. Reply STOP anytime to pause." HELP (without a held answer) is the same text without "You're in." and the steps. The second "Get the Eyes app" text is gone.
- APP and INSTALL still work but are not advertised; both answer "Get the Eyes app: <link>" (/app with TestFlight, /install without). Expired-link fixes say "Text HELP to the Eyes number for a fresh link." The fallback is "Didn't catch that. Reply YES to take a task or STOP to pause. Your setup: <me>".
- Short links: live texts (Inkbox) carry `<public_api_url>/s/<8 base62>` (33 characters on api.eyes.pictures) for every URL on our origins: setup, install/app, payouts, capture, earnings, HERE. Migration 024 `short_links` (id, target, worker_id, expires_at 7 days, created_at; RLS on); `GET /s/:id` redirects 302 to the target (fragment kept) or shows "This link has expired / Text HELP…" (404). Logs and ops events record `/s/<id>`, never the target. Fake messaging (tests, test server) keeps full URLs.
- Keyword typos: a single unknown word matches a keyword at optimal-string-alignment distance 1 (4+ letters) or an adjacent swap (3 letters), only when every match means the same intent ("Strat", "strt", "Start!" → START; "yse" → YES; "hele" stays unknown).
- Kept on purpose: the offer's "Reply YES to claim, STOP to opt out", "Reply NO to give it back" after a claim, and "reply HELP" for a manual review: each appears only when it applies.

## Step numbering (follow-up)
- Live START showed "1. Get the app …" with nothing after it. Steps are now [Get the app, unless the app sent a spot in the last 24 h (location_source 'app', location_at within 24 h); Set up payouts, unless set up or simulated]. Two steps are numbered "1."/"2."; one is a plain line; none opens "You're all set." instead of "You're in." and lists no steps. HELP (without a held answer) sends the same text as START, steps included.
- "Update your spot" is no longer a hub step (the app step covers a stale spot; HERE still texts a fix link).
- A second START/HELP within the hour mints no second code (each one evicts an older device's): the app step links to the setup page instead.
- Tests: engine.int "START and HELP number the steps only when two remain" covers 2, 1 (app sent a spot), 0 (payouts set up too) and back to 1 (app spot over 24 h old) for START and HELP.
