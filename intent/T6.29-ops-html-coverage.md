## Why
The operator dashboard at `/ops` ran about 520 lines of untested inline script in `ops.html`. Coverage could not see it, so release, refund, dispute and filter logic had no tests. The goal: the same behaviour, with every line in modules at 95 or higher on statements, branches, functions and lines.

## What changed
- `apps/web/dashboard/src/ops-view/format.ts`: pure helpers. Money, times, `nearLabel` (coordinates rounded to 3 decimals: "Near 37.761, -122.386"), uptime, tab routing (`tabFor`, `nextTab`), ticket filter (`ticketOpen`, `filterTickets`), event query params (`eventQuery`).
- `apps/web/dashboard/src/ops-view/page.ts`: `boot(win)` holds the rest of the old script: rendering, polling, the review panel (Release/Refund with a confirming second click and a note), ticket actions (Confirm fraud / Reject, Release / Refund / Resolve with note), event log filters and paging, the Leaflet map, tabs with the URL hash, sticky offsets. `document`, `fetch`, `location`, `history` and timers come from `win`.
- `apps/web/dashboard/src/ops.html`: the inline `<script>` is now the placeholder `/* @eyes/ops-view */`. Leaflet still loads with `<script src>` from unpkg.
- `apps/web/dashboard/src/server.ts`: the page CSP (`apps/mcp/src/server.ts`) allows one hash-pinned inline script and no `'self'` scripts. So `opsScript()` reads the two modules, strips types with `node:module` `stripTypeScriptTypes`, drops `import` lines and `export`, and inlines one IIFE that calls `boot(window)`. This is the same place `/* @eyes/ui */` is filled in. The CSP hash is still computed from the served page, so CSP and its test are unchanged. Cost: Node prints one `ExperimentalWarning` for `stripTypeScriptTypes` at startup.
- `apps/web/dashboard/package.json`: `happy-dom` 21.0.3 as a devDependency, for DOM rendering in the tests (no jsdom in the repo).
- Kept as before, on purpose (behaviour must not change):
  - After a review decision, every action button is disabled, then the clicked button's own `finally` enables it again.
  - A dispute ticket with no `dispute_status` shows an "open" badge, but it is not counted as open and has no action buttons.

## Verification
- `format.test.ts` (12 tests) and `page.test.ts` (19 tests) use happy-dom with a routed fake `fetch`, recorded timers and a fake Leaflet. They cover: the full render and the empty/degraded render, 401 to login, feed failure, re-poll skipping unchanged tickets and series, event paging, every review and ticket action including failures and the note requirement, ticket search/status/paging, the event filters and the 300 ms search debounce, tabs by hash and keyboard, and the map without Leaflet.
- `server.test.ts`: `OPS_PAGE` has exactly one inline script with no `import`/`export`. Run against the page body in happy-dom, that script boots, reaches "Live", opens the `#money` tab from the hash and renders the ledger.
- Combined run (`vitest run --coverage --project unit --project contract --project safety --project integration`): `format.ts` 100/100/100/100, `page.ts` 100 statements, 97.72 branches, 100 functions, 100 lines, `server.ts` 100. 1321 tests pass.
- `apps/mcp/src/server.test.ts` (CSP hash over the served `/ops` page) passes unchanged.
