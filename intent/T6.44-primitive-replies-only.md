## Current status (2026-10-18)

The replies-only degradation is implemented. The owner has since verified outbound DNS and delivery to one owner Gmail address; that limited delivery is not unrestricted recipient coverage. `send_to_any_domain` remains false. Preserve the historical denial and checks below; do not request or enable the any-domain flag based on the single-recipient success. See [current email deployment guidance](../docs/DEPLOY.md#4-webhooks).


## Why

The operator reported "Primitive does not work". Inbound works: the webhook endpoint already points at `https://api.eyes.pictures/webhooks/primitive`, and a probe sent from the CLI on 2026-10-18 was delivered (SMTP 250), stored and posted to the API with a valid signature (delivery 1, success 1). Outbound is gated: the org (developer plan) has every recipient gate except `send_to_any_domain`, so an owner's control-link email to gmail.com is refused with `403 recipient_not_allowed`. Agent answers still go out, because the agent emailed first (`send_to_known_addresses`). The org cannot turn the entitlement on through the API or CLI, so it was requested from Primitive by email.

## What changed

- `packages/engine/src/index.ts` `emailOwner`: a recipient-gate refusal (`recipientGateDenial`, exported from the engine) is an expected limit, so it goes to the ops event log as one `info` event per agent (a new optional second argument to `createEyesService`, wired in `apps/mcp/src/main.ts`; no contract change), naming the denied gates (names only; a gate's subject can hold the address). Info events never become Errors-tab issues. `apps/mcp/src/instrument.ts` no longer logs these refusals as `email failed` errors.
- `apps/web/dashboard/src/ops.ts` `redact`: lowercase snake_case words of 32+ characters are kept; live, the 32+ character rule had shown `send_to_primitive_managed_domains` as `[secret]`.
- `apps/mcp/src/server.ts`: `/status` shows "Email: live (replies only until Primitive enables any-domain sending)" unless `PRIMITIVE_SEND_ANY_DOMAIN=1`.
- `.env.example`, `docs/DEPLOY.md` section 4, `docs/vendor/primitive.md`: the gate, how to check `entitlements`, and the switch once granted.

## Verification

- `engine.int.test.ts`: two gate refusals for one agent (signup, then first payer) give one info notice with the three gate names and no address; nothing goes to console.warn or console.error. `instrument.test.ts`: a gate refusal logs no error event. `ops.test.ts`: gate names survive `redact`; mixed-case or digit tokens are still masked.
- `server.test.ts`: `/status` shows the replies-only line by default with live email and plain "live" with `PRIMITIVE_SEND_ANY_DOMAIN=1`.
- Live on a64d2ab (serving since 09:10:43Z): `/status` reads "Email: live (replies only until Primitive enables any-domain sending)". A signup with an owner address on a non-Primitive domain answered 200 with "We could not email your user", and the ops event log has exactly one `warn` for that agent (no error) listing five denied gates; the first showed as `[secret]`, and the warning became an Errors-tab issue. Both are fixed above.

## Known gaps

- The owner control link still reaches the owner only by email, or from the operator (`scripts/owner-link.ts`). This change does not add it to the signup response: ADR-011 keeps the console out of the agent's hands, because the agent could raise its own limits.
- `/status` follows the env flag, not a live entitlement check. Once Primitive grants the entitlement, set the flag and redeploy.
