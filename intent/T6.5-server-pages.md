## Why
The pages the API server renders (home, status, Stripe payout return, top-up done and cancelled, owner controls, new API key, worker earnings) were hand-styled with a dark header and an emoji-like eye mark, so a worker coming back from Stripe onboarding landed on a page that looked unrelated to Eyes. They should share the design system the landing and worker app use. Separately, the Eyes wordmark in a header reloaded the current site instead of taking people to the landing page.

## What
- `packages/ui/page.ts` (`@eyes/ui/page`): `PAGE_CSS` (tokens.css and components.css read once at startup, plus a page skeleton that styles the plain markup the templates already emit) and `PAGE_HEADER` (the viewfinder-bracket wordmark). The API has no bundler, so the CSS is inlined; the pages' CSP already allows inline styles.
- `apps/mcp/src/server.ts` `layout()` and `packages/payments` `shell()` use it; the old per-file style strings are gone. Text, routes, forms, field names and security headers are unchanged. The ops pages are not touched.
- `@eyes/ui` is a workspace dependency of `apps/mcp` and `packages/payments`, so the Docker image (which installs `@eyes/mcp...`) links it.
- Worker earnings page: totals as two large figures, recent tasks as a card list (question, or the task type in plain words; place; bounty; status badge; payout line; claimed time). Dates render in UTC and switch to the reader's local time with one inline script allowed by hash in that route's CSP. Migration 016 replaces `eyes_worker_earnings` (same signature) so each task row carries `question` and `task_type`.
- Owner console: recent tasks as cards with owner-facing status labels, money in and out as a list with signed amounts ("-$3.50") and the task's question instead of a raw id; same local-date script and CSP hash. One-message pages (payment received, payouts set up, cancelled, every error) are a framed card with a "Go to eyes.pictures" button. The invalid top-up link now tells a person to ask their agent for a new link instead of "Call get_balance".
- API home is an API landing: docs as cards (llms.txt, openapi.json, agent-card.json, agents.md), then a people section with "Join to get paid tasks" and "What is Eyes?" (eyes.pictures). Unknown routes answer browsers (Accept: text/html) with an HTML 404 page; API clients keep the JSON error.
- Worker app: design pages carry `noindex`; mood board images are local copies in `public/design/` (hotlinked Commons images rendered empty); the privacy page is titled "Privacy policy" and its lists have bullets.
- `placeName` in `@eyes/core`: a "lat,lng" place label shows as "Near 37.761, -122.386" (3 decimals) on the earnings page and the owner console.
- Worker app: the header wordmark links to https://eyes.pictures, and a coordinate place label ("lat,lng", from agents that ask by coordinates) shows as "Near 37.761, -122.386" on the capture page, rounded to 3 decimals.

## Decisions & alternatives rejected
- One CSS string for every page, not per-page styles: the page set is small and the skeleton targets semantic elements, so templates did not need new markup.
- Read the CSS files at startup instead of copying a subset: one source of truth with the landing and worker app; about 22 KB per page, acceptable for these low-traffic pages.

## Assumptions
- The API process runs from the repo checkout (Dockerfile copies the whole repo), so `packages/ui/*.css` is on disk next to `page.ts`.
