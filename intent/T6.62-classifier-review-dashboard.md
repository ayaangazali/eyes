## Why
Operators need to review a reported classifier block without treating it as a held worker task. The existing Support table, dialog, confirmation controls and dashboard tokens remain the interface. Original question/place, client-reported decision/reason, exact request and server fingerprint are read-only. Untrusted context is rendered as text, not HTML.

## Contract
Only `classifier_feedback` gets Approve and Reject controls. Approval calls the existing `approve_classifier` endpoint and authorizes only the same agent's explicit retry of the exact request within the backend's 24-hour window; it does not dispatch, charge or message a worker. Rejection calls `reject_classifier`; an optional note defaults visibly to “Classifier block upheld by operator.” No release, refund, close or worker-message operation is available for these tickets. Backend validation and binding remain authoritative.

Pending, approved, rejected, expired and consumed states are visible. Failed decisions preserve the note and allow retry; submitted decisions disable duplicate clicks and Escape cannot reset a pending confirmation. Existing task support/dispute controls and the Overview safety slider are preserved.

Controlled-API Playwright tests cover mobile layout, accessible labels, approval/rejection, pending Escape, note preservation and the existing safety slider. The mobile screenshot is produced by the browser test, not production fixture data.
