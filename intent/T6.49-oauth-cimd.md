## Why

Some MCP hosts (Instinct may be one) skip dynamic client registration and send an https URL as `client_id`. Eyes only accepted its own sealed DCR client IDs, so those hosts could not sign in.

## What changed

- `/oauth/authorize`: when `client_id` starts with `https://`, Eyes fetches the document (5 s timeout, 5 KB cap, `redirect: manual`, at most 3 https redirects), requires `client_id` in the document to equal the URL, requires `redirect_uri` to be listed in `redirect_uris` (same https/loopback rules as DCR), and accepts only `token_endpoint_auth_method` `none`. Valid documents are cached for 10 minutes (at most 500 entries).
- SSRF guard: the host must resolve only to public addresses. Private, loopback, link-local, CGNAT, multicast, NAT64 and IPv4-mapped private addresses are refused, for literal IPs and at every redirect hop.
- The consent page shows `client_name (host)`, so a document cannot pass as another app without its host showing.
- Authorization server metadata advertises `client_id_metadata_document_supported: true`. DCR and the token endpoint are unchanged; the code still binds the client_id and redirect_uri.
- `docs/connect/instinct.md`: both client styles listed; CIMD no longer a blocker.

## Known limit

DNS is checked before `fetch` connects, so DNS rebinding between the two is not blocked (marked `ponytail:` in the code). The fetch only reads up to 5 KB of JSON and never returns it to the caller.
