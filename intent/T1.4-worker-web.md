## Why
Workers are the "eyes". They need a page to sign up on, which includes texting START (Inkbox cannot text them until they do, ADR-004). They also need a page that takes a live photo and GPS at the place, so the engine can verify a fresh, on-site answer before paying out.

## What
- `@eyes/web-worker`: a Vite 8.3.4 multi-page app in vanilla TypeScript, with one CSS file. It reads `VITE_EYES_API_URL` and `VITE_INKBOX_NUMBER`.
- JOIN page (`index.html` + `src/join.ts`):
  - Collects the name (checked after trimming), the phone (normalized to E.164; +1 numbers need an area code and exchange that start with 2-9) and location, then sends `POST /w/join`.
  - Step 1 is a tap-to-SMS "Text START" link. It uses `inkbox_number` from the response, falls back to the build-time number, and is hidden if neither exists.
  - Step 2 is plain text saying the payout link arrives by text after START. This follows the engine security ruling on PR #6: `connect_url` is always null and no payout button is rendered.
- Capture page (`capture.html?t=<token>` + `src/capture.ts`):
  - Shows the offer, a map link, the bounty and a live countdown. The page closes when the offer is not `claimed` by this worker, or when the deadline has passed on load or passes while it is open.
  - Takes the photo from a live `getUserMedia` preview with a canvas JPEG shutter. If getUserMedia is missing or fails with anything other than NotAllowedError, it offers the `capture="environment"` file input instead.
  - Shows a "Do not photograph faces" note. Offers yes/no for `is_open`/`in_stock`, plus optional text.
  - Submits as multipart `POST /w/offers/:token/capture`.
- `src/api.ts`: the fetch wrapper. It replaces catalog errors with worker wording for `offer_invalid`, `task_already_claimed`, `invalid_input`, `internal_error` and a default, so workers never see agent-facing fixes.

## Decisions & alternatives rejected
- GPS: each search (on page load, and again after every shutter press) stops at 50 m or better, or after 15 s.
  - The page never discards a fix it already has. A new fix replaces the previous one when its accuracy is within max(previous accuracy, 50 m). A recent good-enough fix therefore beats an older, slightly sharper one taken somewhere else.
  - Send stays disabled until the search ends. A failed search shows "take the photo again", never "reload".
- Send is disabled when `closed || sending || searching || !here || (require_photo && !photo)`.
  - Retakes and new fixes can only call `ready()`, so they cannot re-enable Send during an upload.
  - 404 and 409 responses close the form. Network errors and 5xx re-enable Send. A 2xx shows the result and closes.
- The fallback file input sends the file's `lastModified` as `captured_at`, so a gallery photo fails the server freshness check.
- `@eyes/core` is imported type-only, so the bundle has no zod. Haversine is re-implemented in 5 lines because core `util.ts` imports `node:crypto`. Agent-supplied text is rendered with `textContent` only.

## Assumptions
- Capture links are `{worker_web_url}/capture.html?t=<token>` (confirmed by the engine). The MCP server handles CORS on `/w/*` and maps the `answer_text`/`answer_bool` strings to null and boolean.
- InsForge Sites builds via Vercel over HTTPS (docs/vendor/insforge.md), so the camera and geolocation work.

## Known gaps
- Deploy (T2.3):
  - Set `VITE_EYES_API_URL` (the API base with no trailing slash, e.g. `https://<api-host>`; if unset, calls go to the same origin) and `VITE_INKBOX_NUMBER` (the dispatcher number in E.164) at build time.
  - Build from the repo root, so pnpm can resolve the `workspace:*` devDependency and the lockfile.
- Capture errors other than 404, 409 or 5xx (400, 422, 429) also re-enable Send. The server rejected the request, so a resend cannot duplicate it.

## Follow-up (feat/T1.4-followup)
- Lost response: a capture POST can succeed and then lose its response, so the retry gets `404 offer_invalid` with `status` set to submitted, verified, paid, needs_review or disputed (the engine's `EyesError("offer_invalid", { status })`). That case now shows the "already sent" closed state instead of "link invalid".
- When neither `inkbox_number` nor `VITE_INKBOX_NUMBER` exists, JOIN step 1 shows `opt_in_instructions` from the response, so the START step is never missing.
- An unset `VITE_EYES_API_URL` defaults to "" (same origin) instead of the string "undefined". Checked by building with no env vars: Vite folds the call to `fetch(path)`.
- The final-error spec is parametrized over 409 `task_already_claimed`, 404 `offer_invalid` and the 404 lost-response case.
- Verification:
  - `pnpm exec playwright test --project worker`: 19 passed, and 76/76 with `--repeat-each 4`.
  - Mutants killed: dropping the lost-response branch, and not closing on 404.
  - `pnpm verify:fast` passes.
  - The opt-in fallback is not covered by e2e, because the Playwright web server always sets `VITE_INKBOX_NUMBER`.
