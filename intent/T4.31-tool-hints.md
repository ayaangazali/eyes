## Why
Manufact's MCP Catalog review of the live server (2026-10-17 11:53 PT, catalog entry `eyes`, quality score 91/100, tools section 27.9/30) failed one check, `tool-hints-present`: "6 behavior annotation issue(s) found", one per read-only tool (`quote_task`, `await_answer`, `get_task`, `list_tasks`, `get_balance`, `get_spend_policy`), each "`annotations.destructiveHint` must be boolean". Its hint: "On each tool, declare annotations.readOnlyHint, annotations.destructiveHint, and annotations.openWorldHint as booleans." The six tools set `readOnlyHint: true` and left `destructiveHint` out. The MCP spec treats it as meaningful only when `readOnlyHint` is false, but the catalog and the ChatGPT and Claude directory reviews read the explicit value.

## What
- The six read-only tools add `destructiveHint: false`. No other field, description or schema changes.
- The tools/list test now requires all three hints to be booleans on every tool, so a new tool cannot ship without them.

## Decisions & alternatives rejected
- `destructiveHint: false`, not `true`: they read state only, which is what `readOnlyHint: true` already says.

## Assumptions
- Manufact re-runs the catalog review when the URL is submitted again after a deploy.

- live-verified: no (after deploy, resubmit to the catalog and read `tool-hints-present`).
