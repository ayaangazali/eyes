## Why
Before deploy the app has to run the real Stripe routes and real photo storage, refuse a live start that would silently skip safety and vision, let a crawler or agent find the docs from `/`, and stop wasted or hostile capture uploads before they are read.

## What
- `server.ts`: `stripeRoutes` mounted at `/` (the three-path forward is gone); `liveProviders.storage` is live with `EYES_PROVIDERS=live` plus both `INSFORGE_BASE_URL` and `INSFORGE_API_KEY`; GET `/` home page (pitch, `POST /mcp` with a bearer key, `POST /v1/signup`, doc links); `/robots.txt` and `/agents.md` join the docs routes; every docs response and `/` carry `Link: </llms.txt>; rel="describedby", </openapi.json>; rel="service-desc"`; `url` and `*Url` fields in the agent card that start with `/` become absolute from `public_api_url`, and a malformed card is the clean `not_implemented` 404; docs dir is `EYES_DOCS_DIR` or repo `docs/public`; capture checks the offer (claimed by this worker, status `claimed`) before reading the body and allows 4 uploads at once and 1 per token (429 `rate_limited` otherwise); unknown routes get a JSON 404; `dispute_answer` text says the payout is held only if not yet paid.
- `http.ts`: targets with a username or password are a 400; everything else is rebuilt on `http://localhost` from pathname and search, so Host and authority never reach the app; an unparsable target is a 400 `invalid_input`; logged paths are percent-decoded and then every `[\w-]{16,}.[\w-]{16,}` run is replaced by `<token>`; the adapter's own error log prints only the error name.
- `main.ts`: `createInsforgeStorage(env)` in live mode; exits with a clear message when `EYES_PROVIDERS=live` and `ANTHROPIC_API_KEY` is unset, or when only one of the two InsForge variables is set; `PORT=0` binds an ephemeral port and the log prints the real one.

## Decisions & alternatives rejected
- JSON 404 is a `*` middleware that rewrites Hono's plain-text 404 after `next()`. `server.app.notFound` never runs: mcp-use mounts `server.app` into an outer Hono app with `route("/")`, which drops the sub-app's notFound (reproduced). A catch-all route would shadow `/mcp`.
- The capture pre-check reuses `service.getOffer` and mirrors the engine's own `submitCapture` checks, so the answer matches what the engine would say, only earlier. The upload cap is an in-process counter: one instance in the demo.
- `EYES_DOCS_DIR` is the one new env knob: tests serve fixture docs without touching `docs/public` (owned by ax-builder), and T2.3 can point a `--root-dir apps/mcp` deploy at a copied docs folder. It is listed in `.env.example` on main.
- Token redaction keys on the token shape, not on route prefixes, and runs on the percent-decoded path without slash anchoring, so encoded slashes and dots, full encoding and suffixes such as `;x` or `.json` are covered; the 16-character minimum keeps file names such as `llms.txt` readable. A path that fails to decode is redacted as sent.
- The userinfo 500 came from `new Request()` refusing a URL with credentials, and the adapter then logged that error, URL and token included. Building the Request from pathname and search on a fixed origin removes the cause, and logging `err.name` only removes the leak path.
- The in-flight set holds tokens: its size is the global cap (4) and membership is the per-token cap (1), so one worker cannot hold every slot.

## Assumptions
- Agent card links follow the AX PR #9 layout (`docs/public/.well-known/agent-card.json`, relative `url` and `documentationUrl`).
- `getOffer(token)` throws `offer_invalid` for unknown or expired offers (engine, T1.2).
