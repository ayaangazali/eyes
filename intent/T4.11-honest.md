## Why
The PM audit of the deployed server (fake vendors, no classifier key) found surfaces that claim more than the server does. JOIN took a stranger's phone number and location and then said "text START to the Eyes number" with no number. `/status` and HOME did not say that texting, payments and email are simulated, or that safety review was rules only. `ask_eyes` accepted calls without an `idempotency_key`, so an automatic retry would pay twice. The `location_not_found` fix named a place that does not resolve. Agent docs never mentioned `/status` or `owner_email`.

## What
- JOIN: built without `VITE_INKBOX_NUMBER`, the page shows "Worker sign-up opens soon" and no form, so it never collects a number and makes no request. The form starts hidden and the script shows the form or the closed note. The page now says up front that you need an iPhone (iMessage line). Location help keeps only the iPhone steps.
- `/status` and HOME: a "This is a simulated deploy" box lists texting, payments and email when each is fake, with what that means. `/status` gains a "Safety review: rules only" or "rules and AI classifier" row (`ANTHROPIC_API_KEY` set, same switch as `createAssessTask`), and HOME says the same in one sentence. No env values are rendered.
- Contract (ADR-017): `idempotency_key` required on `AskEyesInput`, with an error message that says what to pass; REST `invalid_input` fix now ends with each failing field and its message; `location_not_found` fix suggests coordinates and "Ferry Building, San Francisco". Tool description, CLI, engine and dashboard test callers updated.
- Agent docs: `llms.txt`, `agents.md` and the openapi description tell agents to check `GET /status`; signup examples include `owner_email` with why. Regenerated `llms-full.txt`, `openapi.json`, agent card.
- README and SUBMISSION: dropped the stale "in review in PR #9" wording; link the live docs.

## Decisions & alternatives rejected
- Closed state decided from the build-time number with no network call, as asked. Rejected: asking the server for its number (`INKBOX_PHONE_NUMBER` on `/w/join`), which would need a new route.
- Removed the "opt_in_instructions" fallback in join.ts: with the form shown only when a number exists, the branch could not run.
- Dropped the Android location sentence instead of reordering: the iPhone steps were already first, and the line is iPhone only (docs/DEPLOY.md), so Android steps only suggested Android works.
- REST fix lists every failing field rather than special-casing `idempotency_key`; catalog `invalid_input.fix` unchanged so signup and capture errors do not mention keys.
- CLI hashes and validates the ask without the key (`partial`), so its auto-generated key and existing pending files keep working.

## Assumptions
- The MCP SDK formats schema issues as `path: message` (`@modelcontextprotocol/server` `formatIssue`), so the zod message reaches MCP clients verbatim. Covered by the server test.
- The e2e golden build on port 4174 is built without `VITE_INKBOX_NUMBER` (playwright.config.ts), so the closed-state test runs against a real build lacking the var.
