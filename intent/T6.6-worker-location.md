## Why
A worker's location was the point they gave at sign-up, forever: offers went to where people joined, not where they are. Inkbox delivers an iMessage "Share My Location" as a lone U+FFFD, so the coordinates never arrive, and the old reply was "Sorry, we did not get that".

## What
- Migration 017: workers get `location_at`, `location_accuracy_m`, `location_source`, `location_token_hash` (sha256, unique) and rate counters; `lat`/`lng` become nullable. `worker_pings` (nonce, worker, task, sent_at, answered_at). `eyes_nearby_workers` and `eyes_reoffer` skip fixes older than `p_max_age` (rows from before 017 count their join time). `eyes_store_location` checks one fix per `EYES_LOCATION_MIN_INTERVAL_S` (30) and `EYES_LOCATION_DAILY_MAX` (1500, a fix a minute all day) in the same UPDATE that stores it. STOP deletes the fix and revokes the token.
- `POST /w/location` (alias `/v1/worker/location` for the Shortcut), `Authorization: Bearer` with a 30-minute signed HERE token or the long-lived per-worker code; body `{lat, lng, accuracy_m?, source, input?, captured_at?}` with numeric strings and comma decimals; 0,0 and out-of-range rejected. 204 / 400 / 401 / 429. The event log records the call and its source, never coordinates. A fix counts as fresh for dispatch at once.
- Texts: HERE, LOCATION, I'M HERE reply with a HERE link; an iMessage that is exactly U+FFFD (or empty with no media) gets "Thanks! iMessage locations don't reach us, so tap this to update your spot: <link>"; START with a stale or deleted fix adds the link; SHORTCUT texts the install link (`EYES_SHORTCUT_URL`) and then a new code alone. Each SHORTCUT adds a code (migration 018, `worker_location_tokens`), so a Mac and an iPhone can each run the Shortcut; the 5 newest codes work and STOP deletes them all. (017 kept one code and every SHORTCUT replaced it, so a second device got 401 every minute.) A submitted capture updates the fix (source `capture`).
- `EYES_LOCATION_PING` (off by default): with fewer than `dispatch_max_workers` fresh nearby, text up to 5 nearest stale workers `Eyes ping <nonce>: ... <HERE link>` (each at most once an hour), and 30 s later offer the task to newly fresh ones. A fix whose `input` contains `Eyes ping <nonce>` marks the ping answered.
- `here.html`: one "Update my spot" button (`navigator.geolocation`), "Spot updated. Near 37.761, -122.386." or the server's error in the worker design system. Privacy pages: latest spot only, from photos, HERE links and the Shortcut; deleted on STOP; spots older than 24 h unused. Ops maps skip workers whose spot was deleted.

## Decisions & alternatives rejected
- Only the latest fix, overwritten in place; no location history table.
- Codes live in `worker_location_tokens` (018) under the 017 RPC names, so the server running before the restart kept working; `workers.location_token_hash` is no longer written (018 copied and cleared it, column kept). `last_used_at` is written at most once a minute.
- `/w/location` and `/v1/worker/location` are named routes in the process log, and their `http` events carry the user agent cut to 60 characters as a device hint (no IP, no coordinates).
- Rate limits in SQL, not in memory, so they hold across restarts and concurrent posts.
- The 30 s re-offer is an in-process timer (`ponytail:` note): a restart in that window loses it.
- `eyes_nearby_workers` / `eyes_reoffer` keep their old argument lists working through defaults, so 017 can go before the server deploy.
- STOP nulls lat/lng instead of keeping the join point: the privacy page promises deletion.

## Assumptions
- `EYES_WORKER_WEB_URL` serves `here.html` (Astro `build.format: "file"`), and its origin is the one `/w/*` CORS allows.
- The Shortcut flow is untested on a real iPhone (docs/research/worker-location.md).

## Verification
- Unit: `apps/mcp/src/server.test.ts` (both routes pass token and body, 204, 401 without a token, 429 passthrough; schema: comma decimals, numeric strings, 0,0, out of range, bad source, junk optional fields ignored). `packages/comms/src/inkbox.test.ts` (HERE / LOCATION / I'M HERE / SHORTCUT intents; U+FFFD and empty-without-media iMessages map to `location_share`, a media message does not).
- Integration (local Postgres, migration 017, `packages/engine/src/location.int.test.ts`): HERE link stores a fix, a second within 30 s is 429, the link expires after 30 min; another token kind and a made-up code are 401; 0,0 and lat 95 are 400; SHORTCUT adds codes: two codes both store fixes, a 6th evicts the oldest, any stored code finds the worker and records last use; STOP deletes the fix and every code; START adds the link when stale; the install link is sent when set; U+FFFD reply; daily cap; stale workers are not dispatched and a new fix makes them eligible at once; a capture updates the fix; pings go out only with `location_ping` on, are recorded, answered by `input`, and `eyes_offer_more` offers the task to the answered worker.
- live-verified: no. 017 is not applied to production.
