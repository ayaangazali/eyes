## Why
Every source file in apps/mcp/src and packages/{engine,core,payments,comms,safety,verify}/src must be at 95% or better on every metric, measured by one combined unit+contract+safety+integration run.

## What
- `apps/mcp/src/instrument.test.ts`: ops event log for providers (texts, email, payouts, vision), safety verdicts and service calls; checks that phone numbers, emails, bodies and coordinates never reach the log, quiet sweeps stay quiet, and EyesError status picks warn vs error. instrument.ts 0% → 100/98/100/100.
- `apps/mcp/src/main.ts`: the boot body moved into `export function start(env, exit)` returning `{ http, stop }`; the process runs it under `if (import.meta.main)` (Dockerfile and `pnpm start` run the file directly, so behaviour is unchanged). `main.test.ts` boots it in-process for every env refusal, fake and fully-live wiring (InsForge db, ClickHouse, Clef vs Claude vision), default HOST/PORT, and the 30 s sweeps logging failures; two spawned boots still check the real process exits 1 and serves. main.ts 0% → 100/100/100/100.
- `apps/mcp/src/server.test.ts`: ops data routes (`/ops/series` from ClickHouse, Postgres fallback and empty feed; `/ops/events` filter sanitising and the in-memory fallback filters; `/ops/tickets` without worker ids and with distance only when both submission coordinates exist; `/ops/tasks/:id` with and without a submission and 404 without querying for malformed ids; resolve rethrowing non-"already resolved" failures; dispute log levels; Claude classifier and non-Error db failures in health), every agent tool and REST mirror forwarding the agent and parsed input, invalid/empty JSON bodies, await_answer progress every 5 s and none without a progress token, short EYES_OAUTH_SECRET refusal. server.ts 87.7/75.9/78.6/89.7 → 99.2/95.7/99.0/100 (unit only).

## Coverage ignores
- `apps/mcp/src/main.ts` `fail` (console.error + process.exit(1)): process exit, reached only by the spawned boot test.
- `apps/mcp/src/main.ts` `if (import.meta.main) start(process.env)`: process entry, reached only by the spawned boot tests.

## Decisions & alternatives rejected
- Tests assert log output through the public `instrument*` functions.
- main.ts: inject `exit` instead of mocking `process.exit`; spawned-process coverage is not collected by vitest's v8 provider, so the in-process `start` carries the coverage.
