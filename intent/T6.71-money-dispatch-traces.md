## Why

Dispatch and payout failures had task IDs in some console messages, but console capture stored no structured task ID.
The engine now supplies task context for offer, notification, location ping, re-offer, payout, and transfer reversal failures.
Console capture validates the task UUID and keeps it in the existing event log.
The existing dashboard event list and task filter can show these records without a UI or schema change.
Payout errors record the error name instead of the raw provider response.

Stripe webhook rejects now produce a log record with the error name or application error code.
These records use `task_id: null`: a rejected signature cannot supply a trusted task ID.
Stripe top-ups and onboarding events are not task events.
Existing webhook status codes, dispatch counts, payout leases, and retry behavior stay unchanged.

## Verification

The payout and notification regression cases failed before the change because their stored task IDs were null.
Tests cover failed offers, failed payout retries, failed paid notifications, rejected webhooks, and valid or invalid task context.
The event log test also checks the existing database write payload.
No production request, migration, or payment is needed for these checks.
