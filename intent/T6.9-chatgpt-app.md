## Why
ChatGPT apps and claude.ai custom connectors need OAuth (static bearer keys are not accepted there) and render rich results only through MCP Apps UI resources. Eyes answers are visual (a photo plus three checks), so plain JSON undersells them.

## What
- One widget resource `ui://eyes/card.html` (`text/html;profile=mcp-app`): the packages/ui tokens, components and icons inlined, plus a small vanilla script that speaks the MCP Apps bridge (`ui/initialize`, tool-input, tool-result, host-context-changed, size-changed) with a `window.openai` fallback. It renders a quote card, a live task card (status steps, photo in the viewfinder frame, answer, GPS/fresh/vision checks, cost) or a balance card. Light and dark follow the host theme.
- quote_task, ask_eyes, await_answer, get_task and get_balance carry `openai/outputTemplate` plus invoking/invoked labels; a `mcp:tools/list` middleware adds `_meta.ui.resourceUri` (mcp-use strips it from tools without an mcp-use React view). Photo CSP allows the InsForge storage host and its CDN. For Claude (client name or user agent contains "claude"), the resource read result carries `_meta.ui.domain` = the first 32 hex characters of SHA-256 of `${public_api_url}/mcp` plus `.claudemcpcontent.com` (Claude's documented rule). Other hosts get no `ui.domain`, because a wrong value makes Claude refuse to render; ChatGPT gets `openai/widgetDomain` and `openai/widgetPrefersBorder`.
- Stateless OAuth 2.1 (`EYES_OAUTH_SECRET`): protected-resource and authorization-server metadata, DCR with an AES-GCM sealed client_id, a login page that takes an existing key or creates one through the signup service (same per-IP budget as `/v1/signup`), sealed 5-minute codes, PKCE S256 only. The access token is the Eyes API key, so the `/mcp` bearer check and existing agents are unchanged. 401 responses carry `WWW-Authenticate: Bearer resource_metadata=...`.

- No workers nearby: the quote card shows a warning "No one nearby" badge, not green "Can ask" (red "Can't ask" stays for refusals). Over MCP only, ask_eyes answers `no_workers_nearby` as a normal result `{status: "not_sent", reason: "no_workers_nearby", charged_usd: 0, message, fix}`, so hosts do not show the call as failed (nothing was created or charged); the widget renders it as a "Not sent" card with the place. REST `POST /v1/tasks` keeps the 409 error. The MCP ask_eyes outputSchema is one object with `status` "dispatched" or "not_sent" (MCP outputSchema roots must be type object), and the description says what not_sent means.

## Decisions & alternatives rejected
- mcp-use views (React + Vite build) rejected: a build pipeline for five static cards. mcp-use `oauthProxy` rejected: needs an upstream IdP plus persistent storage (a DB migration).
- No CIMD: ChatGPT and Claude both do DCR; CIMD means fetching client-chosen URLs.
- Known ceiling: no token expiry or refresh, revoke by rotating the key; a code is replayable within 5 minutes by the same client with the same verifier.
