## Why
Some agents live in an inbox, not an MCP client. Each agent gets a capability address at signup (ADR-007); emailing a question there posts an Eyes task, and the verified answer comes back in the same thread with the worker's photo attached, which is the Primitive track's agent-side email demo.
## What
- `createPrimitiveEmail(env)`: `createPrimitiveClient` with `PRIMITIVE_API_KEY`, sends from `eyes@<PRIMITIVE_DOMAIN>` with `thread.inReplyTo` / `thread.references`. Attachments given by URL are streamed with a byte counter (20 s timeout, 10 MiB cap on the declared size and while reading, the stream is cancelled past the cap) and inlined as base64; the type comes from the download's `image/*` Content-Type (else the caller's), and an extension-less filename gets that subtype. Throws without key or domain, and on `gate_denied` / `agent_failed`.
- `primitiveRoutes` `POST /`, in order: SDK `verifyWebhookSignature` over the raw bytes (`Primitive-Signature`, HMAC-SHA256 over `{t}.{body}`, 300 s back / 60 s ahead, clock from `deps.providers.clock`; missing secret fails closed, 401); `safeValidateEmailReceivedEvent` + `normalizeReceivedEmail`, non-`email.received` -> 200 ignored; sender gate: `isTrustedSender(event, { domain: <From domain>, sender: <From address> }).trusted` (legit DMARC, DMARC domain equal to the From domain or its parent with aligned strong DKIM, strict single-address From parse) and the From domain is not `PRIMITIVE_DOMAIN` or `config.email_domain`, else 200 ignored with nothing processed or sent and no address logged; agent from the first recipient `agentIdFromEmailAddress` accepts; dedupe; then the task.
- Dedupe: event id and `<agent id>:<Message-ID or email id>` kept 24 h in an insertion-ordered map capped at 10,000 keys; a redelivery answers "duplicate" and sends nothing.
- `parseTaskEmail(subject, text, html)`: the first 20,000 chars of the plain text, else of `body_html` (cut before any regex) with style/script blocks, tags and basic entities removed by patterns that cannot backtrack (`<[^<>]*>`). Stops at a line ending in "wrote:" (dropping a wrapped "On ..." line before it), "-- ", "___", "-----Original Message-----", "Sent from my ...", or a "From:" line followed within 3 lines by "Sent:"/"Date:"; skips `>` lines. First `Location:`/`At:`, `Type:` (unknown -> `other_public`), `Bounty:` (USD, "$" and "USD" tolerated) and `Deadline:` (minutes) lines; unreadable numbers become NaN so the schema rejects them. Question = subject minus Re:/Fwd: plus body, 500 chars, surrogate-safe.
- Replies go only to the authenticated From address, never Reply-To, with the subject on one line (CR/LF -> space), capped at 200 chars without a trailing half surrogate pair, In-Reply-To = the agent's Message-ID and References = its chain plus that id (last 20). No location -> instructions worded so the parser cannot read them as a directive; schema failure -> invalid_input naming the fields; `askEyes` error -> message and fix (unexpected errors become `internal_error`); success -> "Got it: task ..., n workers notified, escrowed $x". Every send failure is logged by error code and the webhook still answers 200.
- Background loop after the ack: `awaitAnswer(timeout 55)`; an answer -> reply with answer, yes/no, GPS/fresh/vision flags, distance, confidence, cost and the photo (resent without it if that send fails); any status other than dispatched/claimed/submitted -> one final reply (refund text for expired/refunded, get_task pointer otherwise). Errors sleep 5 s; 5 consecutive errors or 300 rounds end with one "call get_task" reply.
## Decisions & alternatives rejected
- Security review blocker (open relay): replying to Reply-To or an unauthenticated From let anyone with a free signup make Eyes mail arbitrary addresses. Only DMARC-legit mail is processed and replies go to its From. The envelope MAIL FROM was rejected as reply target: providers set it to bounce addresses, and DMARC is what ties the visible From to SPF/DKIM.
- Round 2 (orchestrator ruling): `isTrustedSender` replaces the exact `dmarcFromDomain === From domain` check, so Primitive agent mailboxes like `bot@calm-heron.primitive.email` (DMARC at `primitive.email`, aligned DKIM) are accepted while every round 1 spoof stays rejected; its strict From parse also stops the envelope-sender fallback. HTML is cut to 20,000 chars before parsing because the old tag regex was quadratic (200 KB of `<a` blocked the event loop for 12 s).
- SDK verifier, validator and `isTrustedSender` over hand-rolled code: the note specifies the scheme and the SDK implements it; the validator accepts extra fields and other `version` values (checked against SDK 2.4.0).
- Capability address is the only authorization (ADR-007). Rejected: replying to unknown addresses with "use your signup address" (backscatter).
- No redelivery loops: every reply failure is logged and answered 200. Only an `agentById` failure is a 500, and it happens before the dedupe key is recorded, so Primitive's retry can still post the task.
## Assumptions
- Any local part on the managed domain is a valid `from` (docs/vendor/primitive.md "Addresses"); `eyes@` chosen. `SendResult` has no Message-ID, so `message_id` is null.
- `answered`/`answer` from `awaitAnswer` follow the engine (`ANSWERED` verified/paid/needs_review, `FINAL` expired/refunded/disputed).

## Known gaps
- Pending answer emails are lost on restart (in-memory loop, ADR-007); the agent can still use MCP or REST.
- Dedupe is per process: a redelivery that lands on another instance or after a restart re-sends the ack (the task itself is not duplicated, `askEyes` is idempotent on the Message-ID) and can start a second answer loop.
- If both the answer send with the photo and the resend without it fail, the answer email is dropped (logged); the answer stays available through `get_task`.
- Worker email replies with attachments are out of scope (ADR-007): workers are reached by text only.
- Replies reach only addresses Primitive's recipient gate allows (senders that emailed us with authenticated mail work); cold sends to other domains need `send_to_any_domain` from Primitive staff.
- Agents whose mail does not pass DMARC (no DMARC record, or forwarding that breaks alignment) are ignored without a reply.
