## Why
Some agents live in an inbox, not an MCP client. Each agent gets a capability address at signup (ADR-007); emailing a question there posts an Eyes task, and the verified answer comes back in the same thread with the worker's photo attached, which is the Primitive track's agent-side email demo.
## What
- `createPrimitiveEmail(env)`: `createPrimitiveClient` with `PRIMITIVE_API_KEY`, sends from `eyes@<PRIMITIVE_DOMAIN>` with `thread.inReplyTo` / `thread.references`. Attachments given by URL are fetched (20 s timeout, 10 MiB cap checked on the declared and the real size) and inlined as base64. Throws at construction without key or domain, and when Primitive answers `gate_denied` / `agent_failed`.
- `primitiveRoutes` `POST /`: raw bytes through the SDK's `verifyWebhookSignature` (`Primitive-Signature: t=..,v1=..`, HMAC-SHA256 over `{t}.{body}`, 300 s back / 60 s ahead, clock from `deps.providers.clock`); any failure, including a missing secret, is 401 before any service call. Payload checked with `safeValidateEmailReceivedEvent` and read with `normalizeReceivedEmail`; non-`email.received` or invalid payloads are 200 "ignored".
- The first SMTP recipient that `agentIdFromEmailAddress` accepts picks the agent (`agentById`); forged, shared or unknown addresses are ignored silently.
- `parseTaskEmail(subject, text)`: question = subject (minus Re:/Fwd:) plus body, with quoted lines, "On ... wrote:", Outlook headers and signatures cut, capped at 500 chars without splitting a surrogate pair. `Location:` / `At:` line gives the place (first wins), `Type:` gives the task type (spaces/case tolerated, unknown -> `other_public`).
- In-thread replies (In-Reply-To = the agent's Message-ID, References = its chain plus that id, last 20): no location -> ask for one; schema failure -> invalid_input with the issues; `askEyes` error -> message and fix (unexpected errors become `internal_error`, nothing leaks); success -> "Got it: task ..., n workers notified, escrowed $x". `idempotency_key` = Message-ID (or Primitive's email id), cut to 128.
- Background loop after the ack, never holding the webhook: `awaitAnswer(timeout 55)` until an answer (reply with answer, yes/no, GPS/fresh/vision flags, distance, confidence, cost, photo attached; retried without the attachment if that send fails) or `expired`/`refunded` (reply with the refund). One loop per task per process even if Primitive redelivers.
## Decisions & alternatives rejected
- SDK verifier and validator over hand-rolled code: the note fully specifies the scheme and the SDK implements it; `nowSeconds` keeps the window testable. The validator accepts extra fields and other `version` values (checked against SDK 2.4.0).
- Capability address is the only authorization (ADR-007). Rejected: trusting `From`, or replying to unknown addresses with "use your signup address" (backscatter to spoofed senders, and Primitive's recipient gate).
- Reply target is the parsed Reply-To/From (`replyTarget`): anyone holding the capability can already spend the agent's money, so a different reply address adds no new power.
- After verification, task errors become replies and a 200; a failed reply send or `agentById` failure is a 500 so Primitive retries; retries are safe because `askEyes` is idempotent on the Message-ID and keyless Primitive sends dedupe identical content for 5 minutes.
- `awaitAnswer` errors are logged by error code and retried after 5 s; the loop stops after 300 rounds (about 4.6 h, beyond the 240 min max deadline).
## Assumptions
- Any local part on the managed domain is a valid `from` (docs/vendor/primitive.md "Addresses"); `eyes@` chosen. `SendResult` has no Message-ID, so `message_id` is null.
- Photos are JPEG (`content_type` image/jpeg, filename eyes-photo.jpg); the capture page uses the phone camera.
- `answered`/`answer` from `awaitAnswer` follows the contract; only `expired` and `refunded` end a task without an answer.

## Known gaps
- Pending answer emails are lost on restart (in-memory loop, ADR-007); the agent can still use MCP or REST.
- Worker email replies with attachments are out of scope (ADR-007): workers are reached by text only.
- Replies reach only addresses Primitive's recipient gate allows (senders that emailed us with authenticated mail work); cold sends to other domains need `send_to_any_domain` from Primitive staff.
- No dedupe on Primitive event `id` across processes; covered in practice by the `askEyes` idempotency key and Primitive's 5 minute content dedupe.
