## Why
Live mode texts real phones through Inkbox's shared line, and the first real round trip (G1) is next. The server logs from the stand-in rehearsals on 2026-10-17 show what a failed send looks like today: `inkbox: reply evt_... from ...0142 failed: InkboxAPIError`, with no status and no reason. Worse, a failed offer (`askEyes` and the re-offer after NO) leaves no log line at all: `Promise.allSettled` results are counted and the rejections dropped, so the only trace is `workers_notified` being lower than expected. If the first live offer does not arrive, nothing in the logs says whether the worker has not connected, the line hit a rate cap or the number is wrong.

## What
- `packages/comms/src/inkbox.ts`: an `InkboxAPIError` from `sendIMessage` is rethrown as an `Error` named `InkboxSendError(<HTTP status> <error code>)`, with the SDK error as `cause`. The code is `detail.error`, `detail.code` or `detail.type`, or the detail string, with anything that looks like a phone number replaced by `<number>`, at most 80 characters. Other errors pass through unchanged.
- `packages/engine/src/index.ts`: every rejected offer, in `askEyes` and in the re-offer after a release, logs `offer for task <id> failed: <error name>`; `textWorker` failures log the error name too.
- The webhook route already logs `err.name` for non-EyesError failures, so a failed START, HELP or capture-link reply now shows the Inkbox status and code there as well, with no route change.

## Decisions & alternatives rejected
- The diagnostics go in the error's `name`, not its `message`: every existing log site in the engine and the webhook route logs `err.name` and deliberately not `err.message`, because messages from the reply path can carry a worker's text or number (the route test asserts this). Putting the scrubbed status and code in the name reaches all of them without loosening that rule.
- No retry or alerting: this is visibility for G1 and the demo; issue #30 tracks structured events.

## Assumptions
- `InkboxAPIError` exposes `statusCode` and `detail` (string or object) in `@inkbox/sdk` 0.7.19 (`dist/_http.d.ts`).
