## Why

The widget displayed raw JSON after a failed Ask request instead of a human message and repair instruction.

## Behavior

The shared call and error path parses text, structured and rejected JSON errors. It displays escaped message plus fix, re-enables the clicked button and replaces the previous error on retry. Plain-text errors continue to work. OpenAI and MCP Apps bridges, tool visibility, domains and CSP are unchanged. This release contains no classifier threshold changes.

## Verification

Widget runtime tests click Ask in both MCP Apps and ChatGPT environments. They exercise text, structured and rejected JSON errors, assert human text and escaping, verify retry has only one alert, and confirm the button is enabled again. Existing bridge and task-action tests remain in place.

The host can wrap the tool JSON in `detail` and a Python-style `TextContent(...)` description. The follow-up unwraps bounded JSON layers and extracts only the embedded JSON payload; it never evaluates Python or JavaScript. Click tests replay the screenshot shape, escaped apostrophes/backslashes, structured detail, nested messages and malformed wrappers in both bridges. Malformed wrappers show a retry instruction instead of raw transport data. No classifier setting or threshold semantics change.
