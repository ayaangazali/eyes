## Why
Workers learned about the app from APP/START/INSTALL texts, but without a TestFlight link INSTALL only said the app was in review and no text pointed at the ad hoc install page (T6.31).

## What
While `EYES_TESTFLIGHT_URL` is unset:
- INSTALL (also DOWNLOAD, TESTFLIGHT) mints a fresh app code the same way APP does and texts "Get the Eyes app: https://app.eyes.pictures/install#c=<code>".
- APP and START add a second line "Don't have the app? https://app.eyes.pictures/install#c=<same code>".
- HELP already lists INSTALL.
When `EYES_TESTFLIGHT_URL` is set, the TestFlight texts are unchanged (TestFlight wins).

## Decisions & alternatives rejected
- The install link reuses the app link's code: one code per text, in the URL fragment only, so no server logs it.

## Verification
- Engine integration (Postgres): INSTALL's link carries a working code (`workerDevice` accepts it); APP's second line repeats the APP code on /install; START/APP still mint as before; TestFlight variants unchanged.
