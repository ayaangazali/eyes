## Current status (2026-10-18)

Classifier reporting and operator approval are deployed. Approval still requires an explicit bound retry, runs deterministic safety and spending checks, and never dispatches or charges by itself. See [current MCP status](T6.9-chatgpt-app.md#current-status-2026-10-18); the verification below is the recorded release evidence, not a new live paid-task run.


## Why

Incorrect classifier refusals need human review before dispatch, without inventing a worker, charging the agent, or granting a blanket safety exemption.

## Contract

`report_classifier` reuses the existing Support ticket store. It accepts the original Ask arguments, a separate stable report `idempotency_key`, the original `ask_idempotency_key`, optional existing owned `task_id`, and bounded full `classifier_error`. Context is client-reported feedback, never an authoritative safety result. Reports before dispatch need neither a worker nor a task. Repeated card reports preserve the first payload and ticket ID.

`get_classifier_report` returns only the authenticated agent's report: open, approved, rejected, expired or consumed. The operator approves or rejects through the existing session and same-origin guard; the decision, actor, time, reason and request fingerprint are persisted. Approval lasts 24 hours and never dispatches, charges or sends messages. Existing HELP and dispute behavior remains separate.

An explicit Ask retry includes `classifier_report_id`. The server binds approval to the authenticated agent and normalized question, location, task type, bounty, deadline, photo requirement and original Ask key. Only classifier-layer refusals are bypassed; deterministic rules still run. The existing posting transaction performs spending checks and escrow. A ticket lock links one approval to one resulting task; retries cannot charge twice or authorize changed requests. Failed posting does not consume approval.
