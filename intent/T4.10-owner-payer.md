## Why
The `p:` owner link went only to the `owner_email` the agent picks at signup, so an agent could send its own owner link to an inbox it reads and raise its own limits (issue #38). The one step an agent cannot fake is a human completing Stripe Checkout, so the payer is the trustworthy owner and now gets the link too (ADR-015).

## What
- Contract (ADR-015): `topup.completed` carries `payer_email: string | null`; `creditTopup` takes an optional `payer_email`.
- `parseWebhook` reads `customer_details.email` from the signed Checkout Session; the webhook route passes it to `creditTopup`.
- `creditTopup` credits through `eyes_credit_topup` as before, then emails the payer a receipt ("You added $15.00 to your AI agent's Eyes balance") with the owner link, reusing the signup owner email body. A failed email is logged with agent id and error name only, and never fails the credit.
- Signup owner email and owner console say "Whoever pays for this agent also gets this link."

## Decisions & alternatives rejected
- Email on every top-up, not only the first: it is the payer's receipt, and "first" needs a read no RPC exposes.
- A replayed webhook credits once (ledger unique on `(type, stripe_ref)`) but resends the same link to the same payer; avoiding that needs a migration, and Stripe redelivers only on non-2xx or manual resend.
- `fakePayments.parseWebhook` already passes the signed JSON through unchanged, so `fakes.ts` needed no edit.
- Kept the signup `owner_email` path (ADR-011) so a test-mode agent has a human before any money moves.

## Assumptions
- `Checkout.Session.customer_details.email` is `string | null` in the installed `stripe@23.0.0` `esm/resources/Checkout/Sessions.d.ts` ("The email associated with the Customer ... on the Checkout Session after a completed Checkout Session"). Hosted Checkout in payment mode asks the payer for an email because we pass no `customer` or `customer_email`.

## Known gaps
- The agent-chosen signup link stays valid after a payer appears; no per-link revocation (ADR-011), so the payer can watch and reset limits but cannot lock out an agent that named its own inbox.
- A failed payer email is not retried; the operator can print the link with `pnpm owner-link`.
- Issue #38's other ideas (masked owner email on the top-up page, dropping the agent name from the signup email) are not in this task.
