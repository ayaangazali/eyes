## Current status (2026-10-18)

Historical Cloudflare Containers implementation and verification follow. Production now runs on Manufact Cloud; the Cloudflare Worker forwards to `ORIGIN` and no longer runs the application container. Use [T6.54](https://github.com/ayaangazali/eyes/blob/main/intent/T6.54-edge-forwards-to-manufact.md) and [DEPLOY.md](../docs/DEPLOY.md) for current hosting and deployment instructions. Do not treat the former Mac rollback or container commands below as the current production procedure.

## Why
The live API ran on a Mac (`node apps/mcp/src/main.ts` on :3000) reached through an Inkbox tunnel, so Eyes went down whenever the Mac slept.

## What
- `Dockerfile`: `node:26-slim` (matches local Node 26), pnpm 11.18.0 via npm (Node 26 images have no corepack). `.dockerignore` drops `apps/edge`, so Worker-only deploys do not rebuild or restart the container.
- `apps/edge/api/worker.js`: an `EyesServer` Durable Object (one, named `main`; container `basic`, `max_instances: 1`) starts the container with every Worker secret as env and proxies to port 3000. Until the server has answered once after a start it buffers the request body and retries for up to 60 s, so a webhook during a cold start is not lost. A `* * * * *` cron calls `ensure()` to keep the container running; it makes no HTTP request to the server, so it never appears in the request log or ops metrics. `ORIGIN` set: `api.eyes.pictures` proxies there (rollback to the Mac tunnel) and only workers.dev reaches the container.
- The Worker replaces `x-forwarded-for` with `cf-connecting-ip`: the server rate-limits by the last `x-forwarded-for` entry, and a client-sent value used to pass straight through (a forged header got past the 5-per-hour signup limit).
- Secrets: all non-empty `.env` values except `CLICKHOUSE_*` (the local ClickHouse is unreachable from Cloudflare, so the sink is off on the host).
- Webhooks now point at `https://api.eyes.pictures/webhooks/<x>`: Inkbox subscription d3d028d9, Primitive endpoint (new id 30d48299 after the URL update), Stripe we_1URd1nD15HamYYXUPplesi1i and we_1URd1oD15HamYYXUKYgWwLe4. The Manufact dark-wave Stripe endpoints are untouched.
- `docs/DEPLOY.md`: section 2 is the Cloudflare Containers setup (deploy, secrets, logs, restart, keep-alive); "Roll back to the Mac" replaces "Restart the local server".

## Decisions & alternatives rejected
- Cloudflare Containers over Fly and Manufact: the account was already logged in with containers write and the existing `eyes-api` Worker owns the domain, so no DNS change; Fly and Manufact needed the user to log in.
- Raw `ctx.container` Durable Object API over the `@cloudflare/containers` package: no new dependency, about 60 lines.
- Single instance: in-memory timers and rate limits assume one process; no horizontal scaling.
