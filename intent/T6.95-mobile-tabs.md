## Why

Issue #267: the app was one screen with no navigation, so later items (setup and tasks, sign-in, email, payouts, legal, account deletion) had no place to go.
Expo Router adds the iOS 26 system tab bar with Home, Earn, Spend and Account, each with its own native stack and a large title.
The old `App.tsx` screens move into the Home tab with the same logic.
Earn, Spend and Account are empty states for now.
The look follows Apple's Human Interface Guidelines and the Eyes iOS design notes: semantic system colors, Dynamic Type, SF Symbols, 52 pt capsule buttons, and Eyes yellow only as a fill.

## Decisions

- `App.tsx` renders `ExpoRoot`, so `index.ts` still loads the background task before any screen.
- `expo-router/native-tabs` draws the system tab bar; a shared route group `(home,earn,spend,account)` gives each tab one stack layout.
- `app/+native-intent.ts` sends every system link to Home: the setup link `eyes://connect#c=<code>` would otherwise open an unmatched route. Home still reads that link through `Linking`.
- The location pre-prompt button says "Continue", not "Allow location": HIG says it must not look like the system Allow button.
- `react-dom` is pinned to `19.3.0`: without it, `npm ci` fails on the react-dom 19.3.1 peer of expo-router's web tabs.
- Biome treats `Type` (Text with a Dynamic Type ramp) as a text component.
- No `expo-router` config plugin in `app.json`: the custom root does not need it.

## Verification

`npx tsc --noEmit` in `apps/mobile`, Biome, and the mobile unit tests pass.
A web export of the app shows the four tabs, the Home setup screen, and the three empty states.
