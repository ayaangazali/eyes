## Why

Issue #267: the app was one screen with no navigation, so later items (setup and tasks, sign-in, email, payouts, legal, account deletion) had no place to go.
Expo Router adds a system tab bar with Home, Tasks and Account file routes.
The old `App.tsx` screens move unchanged into `app/(tabs)/index.tsx`, the Home tab.
Tasks and Account are empty states for now, as Apple's Human Interface Guidelines describe.

## Decisions

- `App.tsx` renders `ExpoRoot` itself, so `index.ts` still loads the background task before any screen.
- `expo-router/native-tabs` gives the iOS tab bar (UITabBarController) with SF Symbols, with no icon package.
- `app/+native-intent.ts` sends every system link to Home: the setup link `eyes://connect#c=<code>` would otherwise open an unmatched route. Home still reads that link through `Linking`.
- The colors stay a copy of `packages/ui/src/tokens.css`, now in the tabs layout for every tab.
- No `expo-router` config plugin in `app.json`: the custom root does not need it.

## Verification

`npm run typecheck` in `apps/mobile`, Biome, and the mobile unit tests pass.
A web export of the app shows the three tabs, the unchanged Home setup screen, and both empty states.
