## Why
Issue #89. On 2026-10-17 a Manufact eval on the keyless sandbox (fake geocoder, rules-only safety) had ChatGPT ask Eyes to "photograph the house at 123 Oak St, San Francisco". It got "Eyes couldn't resolve 123 Oak St" (`location_not_found`), not `unsafe_task`. The suite passed for the wrong reason. `askEyes` called `resolve(ask.location)` before `deps.assessTask`, so any place the geocoder could not resolve threw before the safety gate ran. The `location_not_found` fix tells the agent to pass coordinates, which nudges it to retry the same unsafe task. Not a bypass: the retry with `lat,lng` still reaches the gate and the question is refused. But the first answer was wrong, and on the sandbox (fake geocoder, pinned names only) every street address hits it.

## What
`packages/engine/src/index.ts`, `askEyes`: the existing safety check moves into a local `assess(place_label)` that calls `deps.assessTask` and throws `unsafe_task` exactly as before. When `resolve` fails for a string location, `assess` runs on the place text as the agent gave it; a blocked verdict throws `unsafe_task`, otherwise the original error is rethrown unchanged. When `resolve` succeeds, `assess(place.label)` runs once with the resolved label, as on main.

## Decisions & alternatives rejected
- Assess on the failure path only, not before geocoding (issue options 1 and 2): a resolvable place keeps the same classifier input (the resolved label), the same single `assessTask` call and the same order, so nothing changes for working asks.
- Assess when `resolve` fails for any reason with a string location, not only on `location_not_found`: `typeof ask.location === "string"` is the narrowing TypeScript needs to pass the text anyway, and an unsafe task should be refused whether the place was not found or the geocoder (Nominatim) errored. A `{lat, lng}` location never fails to resolve.
- `quote_task` unchanged: it never sees the question, so the issue's case (an unsafe question) cannot reach it, and its result reports a refusal as `allowed: false` beside `resolved_location` and coverage, which do not exist without a place. `ask_eyes` is the gate that checks the question (documented in the `quote_task` description).
- No contract or error-text change: `unsafe_task` and `location_not_found` keep their messages and fixes.

## Assumptions
- On the live server an ask at an unresolvable place now makes one classifier call before returning `location_not_found` (at most one per ask, as on the resolvable path). Unsafe asks at unresolvable places also skip the retry with coordinates.

With the origin/main `index.ts` it fails: expected `unsafe_task`, received `location_not_found`.
