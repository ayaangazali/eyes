## Why
Operator feedback on the dashboard:
- Every list needs search, sorting and filters that survive a reload or a shared link.
- Support actions are hard to use.
- The Workers stat cards look broken.
- Logs are noisy and scroll inside a scrolling page.

The dashboard also moves off the public API host to its own name, https://internal.eyes.pictures, so ops cookies and pages never share a host with the agent API. This phase covers the host move, the shared table with the Review tab, and the two bugs found in T6.29. The other tabs, the Overview redesign and the Logs cursor follow in later phases of this task.

## What changed (phase 1)
- `apps/mcp/src/ops-host.ts`: the dashboard's own host.
  - Default: `EYES_PUBLIC_API_URL` with `api.` swapped for `internal.`. `EYES_OPS_URL` overrides it.
  - On that host, `/x` is served by the `/ops/x` routes. The re-dispatch is marked with a per-process random header, so clients cannot fake it. Nothing else of the API answers there (404).
  - Any other host answers 301 from `/ops*` to the ops host with the same path minus `/ops`. Loopback keeps `/ops`, for tests and local runs.
  - `site(c)` gives the path prefix and the origin that posts must come from.
- `apps/mcp/src/ops-auth.ts`:
  - Login, allowlist, logout and break-glass links, forms and redirects use the request's prefix (none on the ops host).
  - `sameOrigin` checks against the ops origin on the ops host.
  - The `__Host-eyes_ops` cookie is unchanged: Secure, HttpOnly, SameSite=Strict, Path=/, no Domain, so it is host-only on internal.eyes.pictures.
  - Login messages carry only the code, no link, so nothing in them names a host.
- `apps/mcp/src/server.ts`: the host router runs before every other middleware, and `opsAuth` gets `site`.
- `apps/edge/api/wrangler.jsonc`: second custom domain `internal.eyes.pictures` on the same Worker and container. The Worker already forwards `x-forwarded-host`.
- `apps/web/dashboard/src/ops-view/page.ts`:
  - Fetches, logout and header links use the page's prefix: `/ops` when it is served under `/ops`, none at the root.
  - The Review tab is a shared table. Columns: question, place, bounty, checks, status and age. Filters: status, created date range and bounty range. Enter or Space on a row opens the review panel.
  - The table state lives in the hash (`#review?q=..&sort=-bounty&status=disputed`). A tab's state is remembered when you leave the tab and restored when you come back.
- `apps/web/dashboard/src/ops-view/table.ts` (new) is the shared table:
  - pure helpers: `parseHash`, `stateFrom`, `hashFor`, `applyTable`, `nextSort`;
  - `createTable` for the DOM: debounced search over every visible column, header buttons with `aria-sort`, select and range filters (dates as whole local days, amounts in dollars), result count, "Clear filters", rows as buttons;
  - on phones, the filters fold behind a "Filters (n)" button.
- `apps/web/dashboard/src/ops-view/format.ts`: `ago()`. `tabFor` ignores a query after `?`.
- Bugs from T6.29, fixed:
  - After a decision, the clicked button stayed enabled. Now a decided action stays disabled.
  - A dispute ticket with no `dispute_status` showed an "open" badge but no buttons. It now counts as open and gets the dispute actions.
- `apps/web/dashboard/src/ops.html`, layout changes:
  - The page is the only scroller: no fixed-height list boxes. The table filter bar sticks under the tabs.
  - The "available now" stat card lost its yellow left-edge stripe, which looked like a broken bracket. Live counts get an accent dot after the number instead.

## What changed (phase 2: Overview)
- `apps/web/dashboard/src/ops-view/overview.ts` (new) renders the Overview tab:
  - Health:
    - Uptime as the card's key number.
    - One line, "All 6 services live", with one labelled outline icon per service. Each icon has a `title` and `aria-label`, so the state is not shown by color alone.
    - Only a service that is not live gets its own line.
    - Database, safety check and Node are small muted metadata. Commit shows only when it is known.
  - Tasks: a five-step bar strip from Dispatched to Paid, scaled to the busiest step. The accent marks live states.
    - `needs_review` and `disputed`, when non-zero, are links into `#review?status=…`. Otherwise it says "Nothing needs a decision".
    - Every other status goes into one "Ended:" line.
  - Money: escrow held as the key number. The 24 h totals are grouped In (top-ups, escrowed), Out (released, refunded, paid out) and Kept (fees), in one table with a row group each and tabular figures.
  - Trends: bigger cards with plain labels ("Needs review per hour", "Server errors", "Response time, slowest 5%"). Each card has:
    - the latest value large;
    - the line scaled from 0 to its max, with both ends labelled and a dot on the latest point;
    - a tooltip with the bucket time and value under the pointer, also reachable with the arrow keys;
    - an `aria-label` summary.
    - The data source note is now small.
- `packages/ui/icons.svg`: new outline icons `i-mail`, `i-globe`, `i-plug`, `i-error`. `server.ts` inlines the sprite into the ops page in place of `<!-- @eyes/icons -->`.
- `ops.html`: the three top cards share one type scale (title, key number, small muted meta) and one padding. They stretch to one height, and the funnel takes the spare height.
- Design rules applied:
  - interface-design: the layering stays subtle; the bar strip is the one signature element; a squint test on the screenshots.
  - Vercel web interface guidelines: tabular numbers for comparisons; icons are labelled, and status has text as well as color; attention states are real links (deep-linked); accessible charts with an `aria-label` and keyboard access; no dead ends ("Nothing needs a decision").
  - emil-design-eng: no animation on things seen many times a day; the chart tooltip has no delay or transition.
  - frontend-design: no ALL-CAPS eyebrows, no middle-dot meta strings, no identical-card kit; plain labels instead of enum names.

## What changed (phase 3: paged lists API and Logs)
- `packages/db/migrations/023_ops_pages.sql` adds `eyes_events_page`, `eyes_tickets_page`, `eyes_tasks_page` and `eyes_ledger_page`:
  - keyset paging on `(created_at, id)`, newest first;
  - filters and `q` search run in SQL;
  - `total` (and the ledger's `total_cents`) is the filtered count over every page, because the cursor narrows only the outer query;
  - events have no total, since the table grows with every request and the page polls it;
  - 3 `(created_at desc, id desc)` indexes; EXECUTE is revoked from public, anon and authenticated, as in 015.
- `apps/mcp/src/ops-lists.ts`: `GET /ops/events`, `/ops/tickets`, `/ops/tasks` and `/ops/ledger` take `limit` and an opaque `cursor` (base64url of created_at, id and a filter key).
  - A cursor made under other filters, or malformed, gets 400 `invalid_cursor`, so changing a filter resets paging.
  - `/ops/events?since=<cursor>` returns only newer events, plus `newest_cursor`.
  - Tickets and tasks come back without worker ids or answer coordinates; `distance_m` replaces them.
  - The memory-ring fallback for events stays.
  - `server.ts` mounts these lists in place of the old `/ops/events` and `/ops/tickets` handlers.
- Logs tab (`ops-view/logs.ts`, `page.ts`, `ops.html`):
  - one line per event: level icon (info, warning, error) and source icon (web request, MCP, texting, email, payments, photos and so on), each with a title and `aria-label`, then time and the summary cut to one line;
  - Enter or click shows the details: full summary, the redacted data, and "Only task …" to filter by that task;
  - search, source, level and task filters, with the state in the hash;
  - the next page loads when the footer scrolls into view, with a "Load more" fallback and "End of events";
  - pages and live events are merged without duplicates, by id;
  - each poll asks only for events after the newest one shown (`since`), and new events wait behind an "N new events" pill instead of moving the list;
  - only the rows near the viewport are drawn (200 at a time; spacer rows stand in for the rest);
  - a response for filters that have since changed is dropped.
- `ops-view/table.ts`:
  - server-paged mode: no client filtering, a "loaded" count, the footer pager;
  - expandable details rows;
  - windowing;
  - a text filter;
  - the shown tab is the only one that writes the hash.
- Motion, following emil-design-eng (re-read after the 2026-09-15 update):
  - custom `--ease-out` curve;
  - only transform and opacity are animated, all under 300 ms;
  - `scale(0.97)` press feedback on buttons, sort headers, attention links and the pill;
  - row hover only under `(hover: hover) and (pointer: fine)`;
  - the dialog fades and scales from 0.96 (modals stay centered) via `@starting-style`;
  - the pill enters with a small translate;
  - nothing animates on keyboard tab switches or on the poll redraws seen many times a day;
  - `prefers-reduced-motion` keeps fades and drops movement and scale.

## What changed (phase 4: Support and the decision panels)
- Support tickets are a shared, server-paged table.
  - Columns: ticket, kind, state, place, bounty, answer distance, opened.
  - Filters: state (open by default) and kind. Search runs on the server.
  - The cursor pager is at the bottom. A poll refreshes the first page and keeps older pages that are already loaded.
  - The tab and header counts come from `?state=open&limit=1`, whatever the list filters are.
  - A click opens the ticket in the side panel.
- `ops-view/actions.ts` (new) holds the decision area for the review and ticket panels:
  - one primary action per state; the rest sit in a "More actions" menu (`role=menu`, arrow keys, Home and End, Escape);
  - a labelled note: `<label for>`, a hint tied to it with `aria-describedby`; it grows as you type and is required where the server needs it;
  - an inline confirm step in place of the old 5-second armed button: it says what will happen, the confirm button repeats the verb, there is a Cancel, and Escape cancels;
  - a success or error line with an icon; after success the area locks.
  - Ticket states and their actions:

    | State | Primary | Menu |
    | --- | --- | --- |
    | Held help ticket | Release to the worker | Refund the agent, Resolve with note |
    | Other help ticket | Resolve with note | none |
    | Open dispute | Reject the dispute | Confirm fraud (danger) |
    | Review task | Release | Refund the agent |
- Toasts (`createToaster`): one at a time, polite live region, 4 s. They pause while the tab is hidden, rise in and leave faster. With reduced motion they only fade.
- Sign-in and allowlist pages:
  - the CSP allows `font-src 'self'`;
  - `/fonts/*` passes through on the ops host (it is not mapped to `/ops`);
  - the header wordmark lines up with the card's left edge: `--ui-column: var(--eyes-measure)`, with mobile padding to match.
- Bugs found and fixed:
  - a ticket poll dropped older pages once the last page had been loaded;
  - sorting by "Opened" put rows with no date in an unstable order (NaN compare).

## What changed (phase 5: Tasks, Money, Workers)
- `page.ts` has one `pager()` for server-paged lists, shared by tickets, tasks and the ledger. Its behaviour:
  - each page is fetched with the cursor, and rows are deduplicated by id;
  - a filter or search change starts from page 1, while sorting only reorders what is loaded;
  - a refresh with the same filters keeps older pages;
  - a response for filters that have since changed is dropped.
- Tasks: a server-paged table (`/ops/tasks`).
  - Columns: question, place, bounty, worker distance, status, age, agent. Filter: status. Search runs on the server.
  - A click opens the task panel, which now also shows the task's timeline (asked, claimed, answered, released, paid out, refunded).
  - The list refreshes with the feed while its tab is shown, and when you switch to it.
- Money: the ledger as a server-paged table (`/ops/ledger`).
  - Columns: date, type, amount, task (place and id). Filter: type. Search runs on the server.
  - The header shows "$X across N rows" for whatever the filters select, from the server's filtered sum.
- Workers: a table over every worker in the feed.
  - Columns: worker, state, location. Filters: state and location.
  - The map draws only the workers the filters leave (`createTable().visible()`).
