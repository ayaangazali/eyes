## Why
Operator feedback on the dashboard:
- Every list needs search, sorting and filters that survive a reload or a shared link.
- Support actions are hard to use.
- The Workers stat cards look broken.
- Logs are noisy and scroll inside a scrolling page.

The dashboard also moves off the public API host to its own name, https://internal.eyes.pictures, so ops cookies and pages never share a host with the agent API. This phase covers the host move, the shared table with the Review tab, and the two bugs found in T6.29. The other tabs, the Overview redesign and the Logs cursor follow in later phases of this task.

## What changed (phase 1)
- `apps/mcp/src/ops-host.ts`: the dashboard's own host.
  - Default: `EYES_PUBLIC_API_URL` with `api.` swapped for `internal.`. `EYES_OPS_URL` overrides it.
  - On that host, `/x` is served by the `/ops/x` routes. The re-dispatch is marked with a per-process random header, so clients cannot fake it. Nothing else of the API answers there (404).
  - Any other host answers 301 from `/ops*` to the ops host with the same path minus `/ops`. Loopback keeps `/ops`, for tests and local runs.
  - `site(c)` gives the path prefix and the origin that posts must come from.
- `apps/mcp/src/ops-auth.ts`:
  - Login, allowlist, logout and break-glass links, forms and redirects use the request's prefix (none on the ops host).
  - `sameOrigin` checks against the ops origin on the ops host.
  - The `__Host-eyes_ops` cookie is unchanged: Secure, HttpOnly, SameSite=Strict, Path=/, no Domain, so it is host-only on internal.eyes.pictures.
  - Login messages carry only the code, no link, so nothing in them names a host.
- `apps/mcp/src/server.ts`: the host router runs before every other middleware, and `opsAuth` gets `site`.
- `apps/edge/api/wrangler.jsonc`: second custom domain `internal.eyes.pictures` on the same Worker and container. The Worker already forwards `x-forwarded-host`.
- `apps/web/dashboard/src/ops-view/page.ts`:
  - Fetches, logout and header links use the page's prefix: `/ops` when it is served under `/ops`, none at the root.
  - The Review tab is a shared table. Columns: question, place, bounty, checks, status and age. Filters: status, created date range and bounty range. Enter or Space on a row opens the review panel.
  - The table state lives in the hash (`#review?q=..&sort=-bounty&status=disputed`). A tab's state is remembered when you leave the tab and restored when you come back.
- `apps/web/dashboard/src/ops-view/table.ts` (new) is the shared table:
  - pure helpers: `parseHash`, `stateFrom`, `hashFor`, `applyTable`, `nextSort`;
  - `createTable` for the DOM: debounced search over every visible column, header buttons with `aria-sort`, select and range filters (dates as whole local days, amounts in dollars), result count, "Clear filters", rows as buttons;
  - on phones, the filters fold behind a "Filters (n)" button.
- `apps/web/dashboard/src/ops-view/format.ts`: `ago()`. `tabFor` ignores a query after `?`.
- Bugs from T6.29, fixed:
  - After a decision, the clicked button stayed enabled. Now a decided action stays disabled.
  - A dispute ticket with no `dispute_status` showed an "open" badge but no buttons. It now counts as open and gets the dispute actions.
- `apps/web/dashboard/src/ops.html`, layout changes:
  - The page is the only scroller: no fixed-height list boxes. The table filter bar sticks under the tabs.
  - The "available now" stat card lost its yellow left-edge stripe, which looked like a broken bracket. Live counts get an accent dot after the number instead.

## What changed (phase 2: Overview)
- `apps/web/dashboard/src/ops-view/overview.ts` (new) renders the Overview tab:
  - Health:
    - Uptime as the card's key number.
    - One line, "All 6 services live", with one labelled outline icon per service. Each icon has a `title` and `aria-label`, so the state is not shown by color alone.
    - Only a service that is not live gets its own line.
    - Database, safety check and Node are small muted metadata. Commit shows only when it is known.
  - Tasks: a five-step bar strip from Dispatched to Paid, scaled to the busiest step. The accent marks live states.
    - `needs_review` and `disputed`, when non-zero, are links into `#review?status=…`. Otherwise it says "Nothing needs a decision".
    - Every other status goes into one "Ended:" line.
  - Money: escrow held as the key number. The 24 h totals are grouped In (top-ups, escrowed), Out (released, refunded, paid out) and Kept (fees), in one table with a row group each and tabular figures.
  - Trends: bigger cards with plain labels ("Needs review per hour", "Server errors", "Response time, slowest 5%"). Each card has:
    - the latest value large;
    - the line scaled from 0 to its max, with both ends labelled and a dot on the latest point;
    - a tooltip with the bucket time and value under the pointer, also reachable with the arrow keys;
    - an `aria-label` summary.
    - The data source note is now small.
- `packages/ui/icons.svg`: new outline icons `i-mail`, `i-globe`, `i-plug`, `i-error`. `server.ts` inlines the sprite into the ops page in place of `<!-- @eyes/icons -->`.
- `ops.html`: the three top cards share one type scale (title, key number, small muted meta) and one padding. They stretch to one height, and the funnel takes the spare height.
- Design rules applied:
  - interface-design: the layering stays subtle; the bar strip is the one signature element; a squint test on the screenshots.
  - Vercel web interface guidelines: tabular numbers for comparisons; icons are labelled, and status has text as well as color; attention states are real links (deep-linked); accessible charts with an `aria-label` and keyboard access; no dead ends ("Nothing needs a decision").
  - emil-design-eng: no animation on things seen many times a day; the chart tooltip has no delay or transition.
  - frontend-design: no ALL-CAPS eyebrows, no middle-dot meta strings, no identical-card kit; plain labels instead of enum names.
