## Why
The second PM walkthrough found agent and owner surfaces that still sent people the wrong way. An agent that could not afford a task was told no workers were nearby and to move. A key the owner froze (daily cap 0) was told to wait for tomorrow or lower the bounty, which never works. `task_not_found` did not mention `list_tasks`. The console saved a $100 max bounty that `ask_eyes` (max 50) can never use, and replaced the API key on one unconfirmed click. Under fake payments, Add funds and `top_up_url` ended at `checkout.fake.test`, a DNS error.

## What
- Engine `askEyes`: when `eyes_post_task` raises `no_workers_nearby`, re-read the balance; if bounty plus fee does not fit, throw `insufficient_balance` with the numbers and the top-up link instead.
- Daily cap 0: `ask_eyes`'s `daily_cap_exceeded` fix and `quote_task`'s `reason_if_not` say the user froze spending, not to retry, and to ask them to raise `daily_cap_usd` in the owner console. The generic fix now names `daily_cap_usd`.
- `task_not_found.fix` adds "Lost it? Call list_tasks ...".
- `OwnerPolicyInput.max_bounty_usd` max 100 to 50; console input `max="50"` and the invalid-input note say 50.
- Console key replacement needs a required "I understand the old key stops working now ..." checkbox; the server refuses a POST without `confirm=yes` with 400 and the console plus a note, and never calls `rotateApiKey`.
- Fake checkout returns `<success_url>?simulated=1`; `/topup/done?simulated=1` says payments are simulated, no money moved, nothing was added.
- README: $50 max, simulated top-up page, the rotation checkbox, 20 ADRs. SUBMISSION: 20 ADRs. `docs/public/llms-full.txt` regenerated (`cli/src/docs.test.ts` requires it).

## Decisions & alternatives rejected
- Balance after the RPC, not before: `eyes_post_task` answers an idempotent replay before any check, so a pre-RPC balance check would refuse a retry of a task that already escrowed. A new migration reordering the two checks would give the same answer with a 60-line function copy and a database change. Details in the ADR-017 addendum.
- Frozen keeps the `daily_cap_exceeded` code with an overridden fix: no new code for clients and docs to learn. One `FROZEN` sentence serves quote and ask.
- No shared max-bounty constant: none existed, and the card limits schemas.ts to the `OwnerPolicyInput` max. The console's HTML `max` is a literal like the daily cap's 1000.
- The simulated flag is a query parameter on our own page, like `amount_cents`. A page that read the server's provider mode would need new route deps.

## Assumptions
- Hono `parseBody()` returns `{}` for a POST with no form body, so a bare POST counts as unconfirmed.
