## Why
The second fresh-eyes journey audit found four worker-facing rough edges. The JOIN page hides its form when the build has no texting number, but `POST /w/join` still stored a phone and location sent to it directly, so the "collects nothing" promise held for the page only (#12). The claim text never said that replying NO hands a claimed task back, so the release-and-re-offer from #61/#66 only helped workers who happened to send something Eyes did not understand (#6). A broken or expired payout setup link ended with "Expired tasks cannot be submitted", a sentence about tasks (#9). The privacy note said what Eyes keeps but not for how long (#13).

## What
- `POST /w/join` refuses with 501 `not_implemented` when `INKBOX_PHONE_NUMBER` is unset, before parsing or throttling, so nothing reaches `joinWorker`. Message "Worker sign-up is not open yet.", fix "Worker sign-up opens once the Eyes texting line is set up." With the number set, the route is unchanged and still prefers an engine-provided number.
- The worker web maps `not_implemented` to the closed-page wording ("Worker sign-up opens soon." / "Eyes cannot text tasks yet, so we are not taking sign-ups."), for a build that has `VITE_INKBOX_NUMBER` talking to a server that does not.
- Capture-link text now reads "... Never photograph people's faces. Can't make it? Reply NO to give it back. Open: <url>". The capture page already says "Can't make it? Reply NO to the Eyes text to give the task back", so the two now match.
- `workerConnectUrl` with a bad or expired `c:` token: "This payout setup link is invalid or has expired." / "Text START to the Eyes number for a fresh payout setup link." START always texts a fresh payout link (engine `handleWorkerReply`).
- Privacy note gains "How long we keep it": face photos are deleted and never reach the agent (ADR-014); other photos, answers and task records have no end date and the agent's photo link keeps working; STOP stops texts but deletes nothing.
- Every HTTP join outside unit tests now runs with `INKBOX_PHONE_NUMBER`: `e2e/golden-path.spec.ts`, `e2e/demo.spec.ts`, `evals/ax/run.ts`, and the throttle tests in `apps/mcp/src/server.test.ts`.

## Decisions & alternatives rejected
- Existing code `not_implemented` with a message and fix override, the same way the route file already overrides `rate_limited`. No new error code, so no change to `packages/core/src/errors.ts` and no ADR-021 addendum. 501 says "this server cannot do it", which is the case until the line exists; a retry does not help, unlike 503.
- Gate in the route, not in `joinWorker`: the route is where `INKBOX_PHONE_NUMBER` is already read for `inkbox_number`, so page response and gate share one source. In-process `service.joinWorker` callers (engine, payments, dashboard and CLI int tests, `scripts/swarm.ts`) are unaffected.
- Gate before `parse` and `throttle`: a closed server answers the same thing to every request and does not spend a caller's join budget.
- The capture-link line goes before "Open: <url>" so the link stays last; it is a reply after YES, so the 1600-character text limit applies, not the 159-character cold-message rule.
- The payout-link copy lives in the engine (`workerConnectUrl` throws it; `packages/payments` only renders `err.message` and `err.fix`), so the fix is there, next to the earnings link's identical pattern. Overriding in the payments route would have needed a second copy of the text and a code check.
- Privacy copy: no contact or deletion path added, because none exists in code; the note says what STOP does not do instead of promising one.
- `playwright.config.ts` is unchanged: its web servers are the worker web builds; the API in both e2e specs is created in the spec, which is where the env goes.

## Assumptions
- Inkbox text body limit is 1600 characters (docs/vendor/inkbox.md, texts.md). The capture text adds 41 characters to one that was well under it.
