## Why

A successful task photo overwrote the latest GPS source, which the setup page and START/HELP incorrectly treated as installed-app history. Optional email had no persistent way to acknowledge that iMessage alone was wanted. Both are setup-state defects, not delivery failures.

## What changed

- Migration 038 adds two worker booleans: `app_connected` and `email_skipped`. Accepted native location writes set connection once. GPS freshness, source, coordinates, rate limiting, STOP, email retention and dispatch safety stay separate and unchanged.
- Backfill only `location_source = 'app'`, regardless of freshness. Token use, install-link issuance and device registration are not native activity. If a legacy app fix was already overwritten, the next ordinary native report recognizes the connection; no reinstall, new app build or invented history is required.
- `WorkerSetup.app.connected` governs app completion and `workerDevice.app_connected`/START/HELP use the same durable fact. Existing last-at/sending fields remain latest-GPS diagnostics.
- Signed, uncached `POST /w/me/email/skip` with `{}` persists acknowledgement and returns the full setup. No address, verification or mail is created. The existing real email flows clear skipped state when an address is added or verified. The optional UI step shows a checked skipped state after reload and still explains how to add email later.
- STOP still revokes location codes and clears GPS. On the next START an already-connected app gets a fresh reconnect link, preserving completion history while restoring authenticated reporting.

## Verification

- Before the API fix, the isolated regression sent an accepted native fix and then an accepted task photo: completion changed from true to false. The missing acknowledgement route returned 404.
- Real loopback HTTP plus isolated Postgres exercises native fix → photo → other GPS source → reconstructed service → 25-hour passage, negative device/link/rate-limited cases, durable email skip, invalid tokens/origins/body rejection, zero delivery on acknowledgement, and later real email verification.
- Migration regression proves stale native evidence backfills but capture/HERE/unknown history does not. Existing engine/location regressions preserve STOP, freshness and dispatch behavior.
- Mobile and desktop Playwright proof uses the built page and synthetic API fixtures: durable connection after capture, independent stale spot, skipped email across reload with browser storage cleared, request pending/retry/expiry, verified removal and sign-in. It is not live-user or native-device proof.
- Unified lint, types, unit/contract/safety, integration, build and normal PR CI are release gates. Live proof is read-only; never create keys/accounts, send worker messages or write real user preferences for testing.
