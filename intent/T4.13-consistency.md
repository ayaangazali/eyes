## Why
The PR #58 and #59 verdicts and the PM journey audit left sentences that are false on the deployed system (fake vendors, no classifier key): the README signup has no `owner_email`, the worker section describes an open sign-up, the safety section says every task meets a classifier, the owner link is "emailed", an empty or too long `idempotency_key` is told it is "Required", the bad owner link page points at a signup email that was never sent, and nothing tells an agent that only demo places resolve under fake geo.

## What
- README: signup curl sends `owner_email` and says why; `top_up_url` and the console's add-funds button open Checkout once Stripe is configured; the three demo places are named and `/status` is pointed to; generated vs hand-written docs stated correctly; the MCP schema-error exception to `{error, message, fix}`; worker sign-up opens once the texting line is set up ("Worker sign-up opens soon" until then); owner link emailed only when email delivery is set up, also to the Checkout payer (ADR-015), and printable with `pnpm owner-link <agent_id>`; classifier only with `ANTHROPIC_API_KEY`, rules only on the deployed server, `/status` says which; rule and fixture counts corrected (31 patterns, 200 fixtures).
- SUBMISSION: nine tools, not eight; classifier conditional; MCP schema-error exception; which docs are generated; removed the "What's next" payout retry and operator flow item, shipped in T4.2 (ADR-012).
- `schemas.ts`: `.min(1)` and `.max(128)` on `idempotency_key` get their own messages; the "Required ..." text stays for a missing or non-string key (ADR-017 addendum).
- `errors.ts`: `owner_link_invalid.fix` names the signup email, a top-up receipt or the operator (ADR-017 addendum).
- `server.ts`: the simulated-deploy box on `/status` and HOME adds a place lookup line when geo is fake, listing the `FAKE_PLACES` labels and `{lat, lng}` coordinates.
- Agent docs: `llms.txt` and `agents.md` (hand-written) name the demo places, make the owner email and Checkout conditional on live email and payments, and say a task the safety review flags is refused; the llms.txt signup curl no longer breaks on the apostrophe in `<your human's email>`. `docs.ts` builds the openapi description's place list from `FAKE_PLACES` and makes the signup description conditional. Regenerated `llms-full.txt` and `openapi.json`.

## Decisions & alternatives rejected
- Geo line listed from `FAKE_PLACES` in `server.ts` and `docs.ts`, so those two follow the pinned places. `llms.txt` and `agents.md` are hand-written inputs to the generator, not outputs, so their place list is typed out; making them templates would change how they are served.
- Did not tell agents that rules-only safety lets some person or vehicle tasks through; agent docs now only claim that flagged tasks are refused. The README, read by humans, says it plainly.
- `.min`/`.max` messages instead of an `error` function that answers only `invalid_type`: two string arguments, no branching.

## Assumptions
- Zod 4 check-level messages win over the schema-level `error` for their own checks (probed: `""` and 129 chars each get their own message; missing and numeric keys keep "Required").
